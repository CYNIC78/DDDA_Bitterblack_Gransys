## 🎯 Текущий Milestone: Build 85.61 (`85.61-base-diag`)

**85.61** — если прочитанные из памяти статы вида расходятся с файлом игры, лог печатает улики:
здоровье из того же блока, «что мы записали бы сейчас» и каким путём найден блок. Так разбирается
случай «в памяти 400/80/20/20, в файле 250/75/80/75».

**85.60** — база боевых статов вида берётся **из файлов игры** и умножается: таблица на 91 вид
сгенерирована из данных игры, поиск по номеру вида, отсев небоевых карточек. Гадания «наша это
запись или ваниль» в этом месте больше нет — аварийные пути (таблица видов из памяти, оценка)
остались только для видов вне таблицы и подписываются в логе.

**85.59** — линия базы вида: при первом теле каждого вида лог печатает, какие боевые статы
прочитаны из памяти, что из них взято за ваниль и насколько сырое значение расходится с файлом
игры. Поводом стал разбор: эвристика «значение выше порога = наша прошлая запись» умела молча
делить уже изменённое число, и одна сессия ушла с вдвое слабыми гоблинами. Разбор —
[`docs/COMBAT_BASE_INVESTIGATION.md`](docs/COMBAT_BASE_INVESTIGATION.md).

**85.58** — две сводки в логе перестали врать, и список наборов пачки расширен до 12 слотов
(занято четыре, восемь свободны под свои сеты — под будущую привязку к зонам). Книга по огню
больше не считает смертью выход из огня: ветеран, который вышел из огня (`DmgBurnEnd`) и был
убит пешками, раньше попадал в «сгорел» — теперь идёт в «огонь пережил». Строка `pools=stale`
перестала срабатывать на освобождённых телах: stale — только на конкретный чужой вид, а
неразрешённое имя даёт `pools=unverified` (свой ранг печатаем, чужие числа не подставляем).
В итог сессии добавлена строка `Tempo: pack set summary places: … | bodies: …` — раздача
наборов по местам и телам одной строкой.

Действуют: **наборы пачки по месту** (`[packs]`, 85.57) и **живой `[ranks]`** (85.56) —
секции читаются на ходу, уже выданная ступень и набор заморожены за жильцом.
Подробно: [раздел ниже](#ранги-пачки-и-крепость-8540-8551).
Все изменения 85.10–85.57 включены.

**85.21** — PS больше не выводит `RIFTED` из одного `cPlActCmcReturn`: пишет
`CMC_RETURN outcome=unverified` один раз на переход, затем `RAISED after=CmcReturn`

[Контракт прибора](docs/PARTY_STATUS_OBSERVE.md).

**85.10** — source-only: исправлен контекст выбранного Guardian, включая наёмного;

### 84.68 — `monster-cards` (предыдущий)

Тактическая система приказов D-Pad («Ко мне!» / «Вперед!» / «Помогите!») с плавным затуханием (6с decay) и пином целей:

1. **Тактическая система приказов (Tactical Command Engine)**:
   - **«Вперед!» (Go! / F1 / D-pad Up)**: мгновенный пин цели в фокусе прицела камеры/лука Аризена (`uCmc + 0x2EB8`) штурмовым пешкам со скоростным рывком (x1.25). Ситуативный импульс: Scather +300, Pioneer +200.
   - **«Ко мне!» (Come! / F3 / D-pad Down)**: мобильный сбор — отставшие пешки (> 6м) на спринте стягиваются к Аризену в защитную коробку. Ситуативный импульс: Guardian +350.
   - **«Помогите!» (Help! / F2 / D-pad Left/Right)**: мобилизация защиты и приоритет снятия дебаффов/одышки. Ситуативный импульс: Medicant +300, Utilitarian +200.
   - **Плавное затухание (Smooth 6s Decay)**: через 6 секунд веса 100% плавно возвращаются к вашим базовым ползункам без единого байта дрифта в `DDDA.sav`.
2. **Синхронная коробка защиты (Dual-Bodyguard Formation)**:
   - **Guardian (Фронт)**: защищает Аризена от ближних атак и фланкирования.
   - **Nexus (исторический вариант 84.61–84.68)**: перехват угроз возле союзной пешки; кастер выбирался по вокации, не по текущему касту. Nexus не читает `PLAYER-CHANT-HARASS`.
   - В прежнем описании записан результат **35/43 завершённых кастов (81,4%) и 70 перехватов Nexus**. Исходный лог при аудите не найден; это исторический отчёт, не новый замер и не доказательство отдельного вклада Nexus.
   - Текущая политика **85.08**: постоянный напарник и временная аварийная охрана; только ближние исполнители, без собственного ускорения. См. [контракт и ограничения](docs/NEXUS_DOCTRINE.md).
3. **Устранение эффекта "Бенни Хилла" на сабельном раше (`SwMoveAttack`)**:
   - Атака непрерывного бега со взмахами саблей (`cEm0100ActSwMoveAttack`) исключена из ускорения темпа (`factor = 1.0f`).
4. **Гибридный Nuke Gating (Угроза в упор + Одиночный моб)**:
   - Блокировка 15с спеллов при угрозе в упор (< 6м) и на добивании 1 моба.
   - Свобода зачистки сцены (Crowd Wipe) на пачках и боссах.
5. **Оптимизация дистанции HFB (`RangeMinXZ = 4.5 м`)**:
   - Минимальная планка зарядки Focused Bolt установлена на 4.5 метра (`4.5..20 м`).
6. **Общепартийное спасение Аризена (Party Emergency Rescue Protocol)**:
   - Автоматическая мобилизация всех пешек при захвате/нокдауне Аризена.
7. **DDON Return Sanctuary**:
   - 4-кратная броня и x1.30 скорость отхода на спавн у отступающих монстров.

## Что уже работает

### Main Pawn runtime AI

- dynamic `uPlayer/uCmc` discovery через DTI;
- current action/FSM observation;
- 83 pawn AI resources в offline catalog;
- 85 priority rows и 48 live buckets;
- personality/order modifiers;
- generalized persistent profiles из 0..48 exact rules;
- multi-rule transaction, readback, convergence и rollback;
- автоматическое повторное применение после загрузки мира;
- planner current code и indexed `PlanCtrl`;
- 352 weapon/action eligibility rows в generated CSV.

Priority profiles не запускают действие насильно. Они меняют штатный порядок намерений; GOAP, eligibility и FSM сохраняют право отказаться от физически невозможного действия.

### Monster runtime AI — темп движений

Две независимые ручки на каждую особь, обе с жёсткими пределами:

| Ручка | Что меняет | Как | Пределы |
|---|---|---|---|
| скорость передвижения | как быстро монстр сближается и уклоняется | общий asm-hook dash/run/walk + отдельный optional sprint path | 0.75…1.30 |
| темп атаки | замах, удар, восстановление | запись в ряд из пяти множителей воспроизведения (`тело +0x0EE4…+0x0EF4`) | 0.70…1.40 |

- множитель у каждой особи **свой**, детерминирован от адреса тела: стая
  сближается вразнобой, выученный ритм боя не работает;
- темп атаки применяется **только во время атак** (класс действия берётся
  из `ActMap`: 873 состояния, 36 emId-групп, 216 атак), поэтому ходьба
  остаётся ванильной и две ручки не дублируют друг друга;
- пять live-validated legacy wolf actions (`AttackRun`, `Bite`,
  `ContinueBite`, `JumpBite`, `DownBite`) внесены явным allowlist без опасного расширения
  общего regex; proof-лог печатается на входе в mapped attack, а не каждый кадр;
- `animCoupling` связывает ручки: 0 — четыре характера (увалень,
  наскок-отскок, засадный, берсерк), 1 — цельные существа;
- правки **мультипликативные**: торпор и захват продолжают работать поверх;
- пресеты Vanilla / Ragged / Sprinters / Predators;
- цена измеряется в панели: единицы микросекунд на кадр;
- допуск вида перед первой записью, чтобы система переносилась на другие
  виды без риска (`docs/SPECIES_ROLLOUT.md`).

Урон, защита и темп особей в стае балансируются формулами для создания архетипов
(увалень, спринтер, берсерк, джаггернаут) и их гибридов. **Build 85.00+**:
`cCharParamEnemy +0x0C attack, +0x10 defense, +0x14 magick_attack, +0x18 magick_defense`
крутятся через `ApplyCombatStats` с `base * mult * roll(0.9..1.1)`, видовая база
защищает от дабл-мульта при релоаде, Sanctuary поверх умножает боевую защиту на
`armorMult`. Hot-reload из ini работает вживую — инструмент оркестратора жать
игрока в бою, а пешки отвечают командной работой, а не статами.

### Ранги пачки и крепость (85.40–85.51)

Монстры одного вида больше не одинаковы: при спавне каждой особи выдаётся **ранг**.
Ранг — единственное место, где решается, насколько особь крупна, зла и крепка, поэтому
он же и есть ручка сложности.

| ранг | доля в пачке | размер | сила атаки | крепость (Resist / Stand) |
|---|---:|---|---:|---|
| новичок | 34 % | 0.95–1.03 | ×1.00 | 1.00 / 1.00 |
| солдат | 46 % | 1.03–1.07 | ×1.09 | 1.35 / 1.30 |
| ветеран | 13 % | 1.07–1.12 | ×1.20 | 2.00 / 1.95 |
| элита | 5 % | 1.12–1.18 | ×1.35 | 2.65 / 2.60 |
| мини-босс | 2 % | 1.18–1.25 | ×1.52 | 3.30 / 3.25 |

**Новичок — ровно ванильное существо**, без единой нашей поправки: он и эталон, по
которому видно вклад остальных ступеней.

**Кому это доступно (список в коде, ini может только выключить):** гоблин — пилот
(`ranks = on`), волк — с 85.52 с переключателем `[species.uEm0200] rankScale = off`.
У волка ступень меняет **атаку и крепость, но не рост**: волчья стая остаётся волчьей, а
крупные ванильные вожаки сохраняются, как их задумала игра. Хобгоблин и ящер пока вне
списка — их размер тоже неприкосновенен.

**Крепость — это запас, а не броня.** Она не уменьшает урон, а увеличивает количество
яда, огня, оцепенения или толчков, которое нужно, чтобы эффект сработал. Поэтому она
не спорит с формулами урона: урон, защита и элементарные множители остаются ванильными,
а костёр, миазма и добивания продолжают работать. Калибровка ступеней привязана к
реальным числам игры: гоблин горит на 300 и падает от 100, хобгоблин — 2000 и 650,
и **мини-босс-гоблин выходит ровно на половину новичка-хобгоблина** (горение 990,
сбивание 325) — «чемпион лёгкого веса против новичка следующей категории».

**С 85.57 у МЕСТА есть свой набор ступеней.** Одно место карты (ячейка 40 м) = один набор: где-то
почти сплошь новички (`rabble`), где-то половина пачки — ветераны (`warband`), а есть и `hunt` —
элита с мини-боссом. Набор двигает только СОСТАВ пачки: размер, урон и крепость каждой ступени
остаются в `[ranks]`, так что «злее» становится пачка, а не отдельная особь. Тела ближе 25 м друг
к другу всегда берут один набор — пачка не рвётся на границе ячейки. В одном месте не может быть
двух мини-боссов: лишний понижается до элиты (`[packs] minibossPerPack`, 0 = без предела).
Секция `[packs]` читается на ходу, как и `[ranks]`. Слотов наборов — **12** (85.58): занято
четыре, восемь свободны под собственные сеты — свой набор задаётся прямо в ini
(`set4Name` / `set4Weight` / `set4r0..r4` … `set11`) и начинает работать без пересборки.
Раздачу за сессию видно одной строкой в конце лога:
`Tempo: pack set summary places: … | bodies: …`.

Числа рангов и крепости живут в `ddda_ai_overhaul.ini`, секция `[ranks]`: `rankNResist` и `rankNStand`,
где 1.00 = ваниль, без пересборки. Потолки ×3.5. Числа сейчас **общие для всех видов**
под рангами; если понадобится своя лестница виду — это отдельная работа. Поля, которые игра уже сделала почти
иммунными (одержимость, печать навыков — 10000 у обоих видов), код не трогает.

**Дисциплина записи** (почему крепость можно включать без опаски):

- поля игры — **запасы**, поэтому крепче = больше; код только умножает, деления нет;
- карта подтверждена **якорями** — полями, которые мы никогда не меняем (элементарные
  множители, HP): их значения в логе совпадают с файлами игры, а значит и остальное
  прочитано по верным смещениям;
- чтение повторяется до 60 раз: сразу после загрузки зоны движок ещё не заполнил блок,
  и первая пачка иначе осталась бы без крепости;
- после записи идёт **обратное чтение** (`readback pois 1350 froz 1080 burn 405 … (run 1)`) —
  если движок откатит правку, счётчик `run` начнёт расти, и это будет видно.

**Прибор устойчивости.** В логе видны все три события:

| строка | что произошло | проверяет |
|---|---|---|
| `FALL` | сбит с ног (`Tumble*` / `CFall`) | запас сбивания |
| `STUMBLE` | отшатнулся от удара (`DmgStumble`) | запас отшатывания |
| `TRIP` | споткнулся при беге (`RunStumble` / `SlopeFall`) | ничего — это локомоция |
| `BURN-START` / `BURN-SURVIVED` | загорелся / вышел из огня живым | запас горения |

Плюс ранг и запасы прямо в строке смерти, и итоги сессии (`fall summary` — падения, `burn summary` — сколько загорелось, сколько вышло живыми, сколько сгорело). Раньше эти
вопросы решались сшиванием адресов задним числом, а игра переиспользует адреса — такое
сшивание тихо врёт.

Важно различать: прибор видит **падение** (`FALL`) и **отшатывание от урона** (`STUMBLE`), но
не видит короткий **стаггер от блока** или от прыжковой атаки игрока — это разные события
([разбор](docs/STAGGER_KNOWLEDGE.md)). Если ранг не влияет на такую заминку, это ожидаемо, а не
поломка.

**Границы.** Боссы не трогаются вовсе; создание элит и боссов — намеренное решение, а не
побочный эффект. Пачка умеет поднимать тревогу горном и держать захваченную пешку, но
**после смерти вожака никто не разбегается** — и ни одна наша система на это не полагается.
Крупные вожаки, которых игра спавнит сама, сохраняют свой авторский размер.

### Генетический масштаб и индивидуальность стаи (Build 84.44)

Масштаб особи (`тело +0x60 / +0x64 / +0x68`) в MT Framework масштабирует скелет,
дальность шага и радиус хитбоксов:

- **Видовые коридоры в `SpeciesCard`**: гоблины `0.93..1.15`, хобгоблины `0.95..1.14`,
  волки `0.94..1.10`, саурианы `0.95..1.12`. Нижний порог защищает от мажущих хитбоксов.
- **Защита альфа-вожаков (Capcom Leader Immunity)**: если ванильный спавн имеет
  `baseScale >= leaderThreshold` (альфа-волки, крупные вожаки), их авторский размер
  сохраняется (`LEADER_PRESERVED`) и не раздувается.
- **Компенсация частоты шага (Cadence Boost)**: особи меньше `1.0` получают автоматический
  бонус частоты шагов в `MonsterTempo` (`cadence = 1.0 / scale`), благодаря чему легковесы
  чаще семенят ногами, не отстают от стаи и ощущаются шустрыми загонщиками.

### Monster director

`src/monsterai/MonsterDirector.{h,cpp}` — сторона монстров, симметричная
оркестратору пешек. Обе стороны читают **одну шину** (`CombatBus`). Стратегия
сохраняет принятую momentary absolute-HP priority и hysteresis-held `PackMark`:
`isolation` определяет NONE/BIAS/FOCUS-WINDOW, а `targetDepth` остаётся
диагностикой.

Отдельный `TacticalCues` — маленький универсальный table-driven matcher, а не
wolf-условие внутри Director. Таблица сохраняет проверенные тактические рецепты:
- `cPlActGrabStart` / `cPlActHagaijime` + exact `uEm0100` → `GOBLIN-GRAB-ALERT`;
- `cPlActGrabStart` → `PACK-GRAB-ALERT`;
- `cPlActHagaijime4Feet` → `PACK-GROUND-PIN-ALARM`;
- `cPlActLift* + cEm0200Lifted` → `PACK-LIFT-RESCUE`;
- `cEm0100ActHorn*` + exact `uEm0100`/`uEm0101` → `GOB-HORN-ALERT` / `HOB-HORN-ALERT`;
- `cEm0200Howling` / `cEm0400ActFriendHowl` → `WOLF-HOWL-ALERT` / `SAURIAN-HOWL-ALERT`;
- `cPlActWpnWandBase` / `MagicBow` / `MagicShieldBase` + Arisen only → `PLAYER-CHANT-HARASS`.

### Pawn tempo compensation (`[pawnHaste]`)

У пешек в бою **нет спринта**: планировщик коды рывка (`84 DashFollow`,
`85 DashFollowSt500`) не выбирает никогда, а строк приоритета у них нет ни
одной из 85. Все пойманные рывки приходят под кодом `1 Follow`.

Раз дыру в мобильности мы усугубили сами, ускорив монстров, — модуль её и
компенсирует:

| ключ | что делает |
|---|---|
| `matchMonsterTempo` | множитель равен множителю самого быстрого врага рядом; монстры ванильные — компенсации нет вовсе |
| `animCouple` | вместе с перемещением ускоряется **анимация бега**: поле `[0]` ряда `+0x0EE4` (покой 1.000, шаг 1.060, бег 1.150) |
| `requireWeaponDrawn` | признак боя у самой пешки (`cPlActHoldWeaponMv`, семейство `cPlActWpn*`) ИЛИ подтверждение детектора — враги за стеной не триггерят |

### Caster AI range (`[errata] wandRange`)

Пешка-маг/чародей: живой `cCmc* +0x258`, RangeMax **1–10 м → 15 м** (как лук).
Все `uCmc`. Касты включая Anodyne/Levin/Focused Bolt; **IceWalk** (Frigor) короткий.
Игрок, снаряд, StandOff, мили — нет. Галка в F12 / `wandRange = on`.

## Важные ограничения

Проект — development milestone, а не законченный пользовательский AI overhaul.

Что уже работает (Guardian Doctrine & Rescue Protocol):
- трекинг игрока/пешки/врагов + диспозиция боя;
- двухуровневый защитный периметр (Critical Melee 4–6м, Preempt Intercept 6–12м);
- общепартийное спасение Аризена при захватах и нокдаунах;
- ролевая матрица (вокация пешки × вокация игрока): Protector/Assault/Adaptive/…;
- градиентная зона телохранителя (preempt/melee) со снятием Guardian-штрафа транзакционно;
- трёхсигнальный детектор боя (урон + боевые действия врагов + цель пешки).

Ещё не завершены:
- **человеческие враги** — оружие, вокации и аугменты образуют отдельную систему; темп на них намеренно не переносится;
- Nexus: дистанционные исполнители, арбитраж и подтверждение новой политики 85.08 в игре;
- monster priority/planner bridge.

## Сборка

1. Открыть `ddda-ai-overhaul.sln` или `.vcxproj` в Visual Studio.
2. Выбрать **Release | Win32**.
3. Build Solution.
4. Скопировать `dinput8.dll` в папку с `DDDA.exe`. **Ini копировать не нужно** —
   мод создаст `ddda_ai_overhaul.ini` сам и допишет новые ключи при обновлении,
   не трогая уже выставленные значения. Файл `ddda_ai_overhaul.default.ini` в
   репозитории — только справочник.

> **Сверяйте тег.** Первая строка лога печатает `MOD_BUILD_TAG` — это
> единственный надёжный способ убедиться, что игра запустила именно ту
> DLL, которую вы собрали.

Подробно (требования, установка в игру, разбор ошибок): [`docs/BUILD_INSTRUCTIONS_RU.md`](docs/BUILD_INSTRUCTIONS_RU.md).

## Принципы безопасности

- не сохранять heap pointers;
- не менять `DDDA.sav`;
- не угадывать offsets;
- validate → write → readback → convergence → rollback;
- unknown version/object → vanilla fallback;
- `game_main.arc` repack — только резервный PACK-путь.
