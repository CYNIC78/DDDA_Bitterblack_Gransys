Build 66 — охота за интентом (Pioneer-обгон и Guardian-прилипание)

Собрать:
  Visual Studio → Release | Win32 → Build Solution

Проверить в F12:
  build 66-intent-hunt-all

ЗАЧЕМ
=====

Поводок — не поле, а СЛЕДСТВИЕ выбора intent. Но мы так и не вскрыли:
  - Pioneer: какой intent заставляет пешку вырываться ВПЕРЁД по камере?
  - Guardian: какой intent удерживает её у игрока?

Теперь ловим СМЕНУ ИНТЕНТА (code) — любой код, не только 4/66. Логируем
каждый переход: код + имя + exact action + target + GOAP-имя.

ЧТО ДЕЛАТЬ
==========

IntentHunt работает ВСЕГДА в фоне (read-only). Просто играй и смотри в лог
строки «IntentHunt: code=...».

Тест 1 — Pioneer (выкрути Pioneer высоко, Guardian низко):
  1. Беги вперёд, камеру держи по ходу движения → пешка обгоняет.
     Смотри в лог: какой code в этот момент? (ожидаем DashFollow/StandOff/Goto)
  2. Разверни камеру на пешку → она плетётся сзади. Какой code теперь?

Тест 2 — Guardian (выкрути Guardian высоко, Pioneer низко):
  1. Просто стой/иди рядом → пешка «липнет». Какой code? (ожидаем Follow)

В панели Guardian Doctrine строка «code N (имя): action=...» покажет последний
сменившийся intent. В логе — полная история переходов с GOAP-именами.

ЧТО ПРИСЛАТЬ
============

1. Компилируется ли.

2. Из лога: строки «IntentHunt: code=...» в двух фазах:
   - Pioneer-обгон (пешка впереди) — какой code/action;
   - Guardian-прилипание (пешка у игрока) — какой code/action.

3. Отметь, какие GOAP-имена появляются (links=... DashFollow? Follow? Goto? StandOff?).

По этому я пойму, ЧЕМ управлять: какой code поднимать/опускать для
роль-зависимого позиционирования (якорь=камера vs якорь=игрок).

read-only, ничего не пишет в игру.
