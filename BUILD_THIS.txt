Build 60 — быстрый поиск позиций + фикс 0,0,0 + чистка лога

Собрать:
  Visual Studio → Release | Win32 → Build Solution

Проверить в F12:
  build 60-positions-fast-fix

ЧТО ИСПРАВЛЕНО
==============

1. СКАН СТАЛ БЫСТРЕЕ (главное)
   - Для позиций (PartyPositionsTick) census теперь в fast-режиме: ранний
     выход, как только найдены ОБА тела (uPlayer + uCmc). Раньше сканировал
     весь адресный диапазон до 0x7FFF0000 (~1.5-2 с) ради priority/targetSel,
     которые позициям не нужны. Теперь ~в разы быстрее (останавливается на
     адресе второго тела).
   - Полный census остался только для priority-профиля и кнопки аудита
     (там нужны все кандидаты).

2. ФИКС БАГА 0,0,0 (холодный старт)
   - Раньше, если тело пешки становилось невалидным БЕЗ смены мира
     (пересоздано в бою/воскрешении), позиции висели 0,0,0 до перезагрузки:
     сброс тел был только на переходе «мир выгружен».
   - Теперь: если кэшированное тело не прошло проверку vtable — НЕМЕДЛЕННЫЙ
     пере-резолв без троттла.
   - При неполном наборе (пешка ещё не спавнилась) — бэкофф повторов
     2с → 8с → 20с (раньше постоянные 5с, каждый раз полный скан).

3. ЧИСТКА ЛОГА
   - «pawn read FAILED» теперь пишется ТОЛЬКО при переходе в сбой (было ок
     → стало не-ок) или раз в 60с, а не каждые 3 секунды (это и был спам).

ЧТО ПРОВЕРИТЬ
=============

1. Компилируется ли.

2. Холодный старт: запусти игру → загрузи сейв → открой «Guardian Doctrine».
   Позиции обеих сторон должны появиться быстрее, чем раньше, БЕЗ фризов.
   И главное — не должно быть 0,0,0 (если и появится на долю секунды —
   должно самовосстановиться за пару секунд).

3. Лог: при нормальной работе «pawn read FAILED» должен встречаться максимум
   1 раз (на переходе), а не спамить.

4. Побейся (бандиты/волки) — позиции и зона должны работать стабильно.

ПРИМЕЧАНИЕ
==========

Fast-режим останавливается на ПЕРВОМ uCmc — это корректно, пока в группе
только главная пешка (наёмные пешки — вне scope, как и раньше).
