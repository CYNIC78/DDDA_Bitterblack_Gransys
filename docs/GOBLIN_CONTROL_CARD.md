# Панель управления гоблинами — одна страница (85.47)

Система крутится тремя независимыми слоями. Каждый правится в ini, каждый
можно выключить одной строкой. Пересборка нужна только для НОВОГО вида.

--------------------------------------------------------------------------------
## Слой 1. ТЕМП: как быстро воюет и двигается

Файл: `ddda_ai_overhaul.ini`

| где | что | зачем трогать |
|---|---|---|
| `[monsterTempo] factorMin/Max` | разброс скорости передвижения всех видов | «все монстры быстрее/медленнее» |
| `[monsterTempo] animFactorMin/Max` | разброс темпа замаха всех видов | «все бьют чаще/реже» |
| `[species.<вид>] rageLocoMin/Max` | до чего особь разгоняется ПО ПРИКАЗУ | «пусть реакция на событие будет заметнее» |
| `[species.<вид>] rageAnimMin/Max` | то же для замаха | «пусть на приказ бьют резче» |
| `[species.<вид>] tempoRage = off` | выключить разгон виду целиком | если вид перестарался |

Числа подбираются по шпаргалке: `docs/TEMPO_GOBLIN_HOB_RANGES.md` §7
(она же продублирована в самом ini). Правило одно: потолок выше базового
верха = приказ виден.

--------------------------------------------------------------------------------
## Слой 2. РАНГИ: кто в пачке главный

Файл: `ddda_ai_overhaul.ini`

| где | что |
|---|---|
| `[species.<вид>] ranks = off` | выключить ранги виду (включить может только код: вид в списке) |
| `[ranks] rank0..rank4 Weight` | какая доля пачки — на ранге (`Weight`) |
| `[ranks] rank0..rank4 SizeMin/SizeMax` | полоса роста ранга (главный знак) |
| `[ranks] rank0..rank4 Atk` | множитель атаки ранга |
| `[ranks] rank0..rank4 Resist` | во сколько раз крепче к дебаффам (1.00 = ваниль) |
| `[ranks] rank0..rank4 Stand` | во сколько раз крепче к сбиванию (1.00 = ваниль) |

Ранги: `rank0` новичок → `rank1` солдат → `rank2` ветеран → `rank3` элита →
`rank4` мини-босс. Ранги — инструмент РАЗМЕРА, поэтому вид допускается списком
в коде (сегодня только гоблин): ini может выключить, но не включить. Волк, хоб и
ящер в список не входят — их размер неприкосновенен, ключ не читается.

Правила, которые ранги соблюдают сами: ниже ванили не опускает, рост не выше
1.40 (предел движка).

**Крепость (`Resist` / `Stand`, 85.44; направление уточнено полем в 85.45).**
Ключ читается как «во сколько раз крепче»: 1.00 = ровно ваниль, больше = крепче,
меньше 1.00 зажимается обратно. Одно число на ранг вместо 27 ключей — направление
полей переводит код. Потолки: x3.50 на оба (подняты в 85.47 под калибровку «половина хобгоблина»).

**Волки (85.52):** ранги включены, но **размер не трогается** — `[species.uEm0200]`
`ranks = on` + `rankScale = off`. Волк получает атаку и крепость по ступени, а рост
остаётся ванильным (крупные вожаки от Capcom сохраняются). Числа крепости те же, что у
гоблина; на родных запасах волка это горение 400 → 540/800/1060/1320 по ступеням.

**Лестница включена в 85.47 и откалибрована по хобгоблину:** новичок 1.00/1.00,
солдат 1.35/1.30, ветеран 2.00/1.95, элита 2.65/2.60, мини-босс 3.30/3.25.
В переводе на родные числа — горение у мини-босса 990 против 2000 у хобгоблина, а
сбивание 325 против 650: ровно половина следующей весовой категории, как и просил
владелец. Огонь при этом работает: 990 — всё ещё в шесть раз горючее, чем у хоба.

Родные числа игры (подтверждено якорями в поле 85.45: тьма 0.60 и HP 1000
прочитались ровно как в файлах игры): яд 1000 · **горение 300** · заморозка 800 ·
окаменение 700 · одержимость 10000 · печать навыков 10000 · отшатывание 100 ·
сбивание 100. Это ЗАПАСЫ: больше = крепче. Игра сама строит лестницу крепости
между видами — у хобгоблина 3000 / 2000 / 3500, у волка к яду 600, у сауриана
10000. Наши ранги продолжают эту лестницу внутри вида.

Элементный УРОН (огонь/лёд/…) — другая семья, там «меньше = крепче» (у волка
огонь 1.1, у сауриана тьма… 0.6). Мы её не трогаем вообще.
Пока вид под рангами — `scaleMin/scaleMax` из `ddda_entities.ini` для него НЕ
применяется: разброс задаёт ступень.

## Слой 3. СИЛА И ЗАЩИТА: цена ошибки и запас прочности

Файл: `ddda_entities.ini` (читается на лету, перезапуск не нужен)

| где | что |
|---|---|
| `[default] attackMult / defenseMult` | общая база ВСЕХ монстров (сейчас 1.12 / 1.0) |
| `[class.boss]` | боссы — зафиксировано 1.0, не трогаем |
| `[emXXXX] attackMult` и т.п. | конкретный вид |
| `[emXXXX] adrenalineAtk / adrenalineMagick` | всплеск атаки по приказу (до ×1.6) |

Дальше по запасу: у нас есть и полностью независимые защиты вида — огонь, лёд,
яд, горение, устойчивость к сбиванию и флинчу (карта полей:
`docs/ENCOUNTER_MEMORY_DESIGN.md` §8.7). Они не подключены как ручки: понадобится
поднять сложность отдельного вида «не трогая атаку» — это следующий рычаг.

## Как это выглядит в логе (проверка, что всё живо)

```
Monster Director: species uEm0100 rage ceilings run 1.15..1.20 swing 1.15..1.24
Monster Director: ranks uEm0100 ON novice w0.34 0.95..1.03 x1.00 | soldier w0.46 ... | ...
EnemyTuner: rank uEm0100 veteran(2) size 1.096 atk x1.20 -> 0x...
EnemyTuner: scale 1.096 (base 1.000 RANK) -> uEm0100 0x...
Tempo: rank summary total=10  uEm0100:2 5 1 0 2      <- кто заспавнился за сессию
EnemyTuner: resist uEm0100 0x11122AE0 fire 1.00 | pois 1.00 ... | flinch 100.0 kdown 100.0
                                                    <- родные числа игры (85.44), один раз на особь
EnemyTuner: resist applied uEm0100 0x... res x1.20 stand x1.00 wrote 22 readback burn 0.83
                                                    <- появляется только когда ручки не 1.00
EnemyTuner: resist uEm0100 0x... not ready (field 11 val 0.00) - will retry
                                                    <- 85.46: блок ещё не заполнен движком,
                                                       код попробует снова (до 60 раз)
```

--------------------------------------------------------------------------------
## Что упростилось в 85.40–85.44 (убрано, а не спрятано)

* компенсация частоты шага — **удалена** (вместе с ней снят и пол 1.0);
* размер — **ступень + ±2 % комплекция** вместо равномерного коридора;
* три формулы → одно значение. Осталось три слоя ручек, все в двух ini.

## Откат

* ранг вида — `ranks = off` (без пересборки);
* весь билд — архив `85.39` / `85.38` из `builds/` (архивы не удаляются).
