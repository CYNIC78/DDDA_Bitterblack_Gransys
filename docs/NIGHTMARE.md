## Чего кнопка не умеет (честно)

thiscall берёт **id**. Каталог на 40 слотов. Inflict **доказан только для 7**.
id=6 (Drenched) мы **слышали** как ванильный refresh, сами не вешали.
Любой другой id — отдельный A/B, fail-closed если движок стирает.

Параметры каталога при вызове **не передаются аргументами**. Функция
читает ресурс в xmm0/1/2 (секунды, p0, p1), потом пишет слой C.

dinput8 `HBuffMods` **не вешает** статус. Он сидит **после** загрузки
каталога в xmm и, если слот id включён, подменяет:

```text
esi = id
xmm0 = Timer   xmm1 = Param0   xmm2 = Param1
гейт: [body+0x3DEC]+8  (cCmcInfo, слот партии ≥ 0)
```

Игра сама решила apply/refresh — мод только подкрутил числа. Поэтому
«при следующем вызове статус берёт таймер мода». Inflict у них нет;
у нас есть (thiscall). Наш хук 84.32 — **тот же сайт**, пока listen.

Следствие для градуса: stage может писать xmm **только на нашем Set**
(не на ванильный Drake). Drenched в воде refresh каждый тик каталогом;
Possession в 84.34 — **один** `BuffApply id=7`, дальше тикает запись.
Значит одноразовая подмена xmm на нашем вызове имеет шанс держаться
до конца таймера. 84.37: путь в коде (`customParams`, F12 timer/p0/p1). Live A/B ещё нет.

`p0=0.2` согласуется с вики «мили режется»; `p1=0.35` — UNVALIDATED.

«Сильнее с каждым приступом» ≠ крутить CORE STR/DEF записи (`+0x984/+0x988`).
Пока нет A/B: длительность приступа = **наш** Clear по таймеру sidecar,
не правка каталога.

## Состояние мода живёт в sidecar

Не в `DDDA.sav`. Не в листе персонажа навсегда.

Ванильный статус **не** переживает загрузку сейва. После load мы сами
решаем, вешать ли id=7 снова — из **нашего** файла рядом с DLL/ini.

```text
DDDA_AI_Overhaul/nightmare_latch.ini     // или один ключ в ddda_ai_overhaul.ini
  vector     = 0|1     // BBI-лут побывал в Грансисе (ещё не детектор)
  stage      = 0..N    // градус скверны главной пешки
  episodes   = int     // сколько приступов уже было
  last_set   = unix    // не для геймплея, для отладки
```

Наёмные: без постоянной метки верности (`HIRED_PAWNS_SCOPE`). Только Main
Pawn, пока не скажем иначе. Честный поход без вектора — иммунитет
(VISION).

Unload / `enabled=off` → Clear статуса, latch на диске **не** обязан
стираться (иначе NG и перезаход в лагерь лечат сюжет). Стирает только
явный сброс / NG+ политика — когда напишем.

## Градус заражения (пешка) — замысел, не код

Один статус id=7. Разница приступов — **когда** Set и **когда** Clear,
не другой id.

| stage | Приступ | Длительность (наш Clear) | Заметка |
|---:|---|---|---|
| 0 | нет | — | нет вектора / верность |
| 1 | вспышка | коротко (десятки секунд) | знак, не бой на 3 мин |
| 2 | приступ | минуты, меньше каталога 180 | уже враг |
| 3 | полный каталог | 180 с или до KO | финал ночи / высокий метр |

Бюджет боя (VISION): за один бой одержима **не больше одной** пешки.
Две — только после уже виденного первого раза. Три — не стычка у Кассардиса.

«Тем сильнее в бою» — **открыто**. Кандидаты, каждый со своим A/B:

1. дольше держать Set (stage↑) — уже можно Clear-ом;
2. live timer/p0 на записи **после** ванильного apply (84.31 poke без apply
   стирался; после apply — не пробовали);
3. заполнить `cStatusParam` (28 B, `this` вызова) до thiscall — UNVALIDATED.

Пока 2–3 не закрыты, stage двигает только длительность приступа.

## Когда Set (ещё думаем)

Не на `cPlReviveCMC`. Не от воды. Не без вектора.

```text
нет вектора / верность / !InWorld          → Set отказывает
в бою + вектор + Neardeath/Dead            → latch (sidecar), статус ещё нет
подъём (ваниль лечит, если был id=7)       → latch жив
первый бой, пешка на ногах                 → Possession::Set (id=7)
наш таймер stage / KO / clear / unload     → Clear
```

Триггер вектора (BBI-лут в Грансисе) и «органичные» поводы приступа —
фантазия впереди. Сначала детектор лута, потом расписание. Кнопка F12
остаётся отладкой.
