# Тест 07 — «запись идеальная, эффекта нет»

## Симптом

Билд 20. Кнопка `FORCE scale 0.60` отработала безупречно:

```
ForceScale: body+0x60 before=(1.000,1.000,1.000) wrote=0.600 fields=3 after=(0.600,0.600,0.600)
EnemyTuner: scale 1.234 -> body 0x10DD0060 (3 fields) was=1.000 applies=1 reverts=0
```

Прочиталось ровно то, что записали. Держится: `reverts=0`.
**Гоблин на экране не изменился.**

## Почему это сбивало с толку

Три предыдущие итерации мы искали причину в природе поля:
«движок откатывает», «поле читается только при спавне», «не то поле».
Лог закрывал все три версии сразу:

| наблюдение | что исключает |
|---|---|
| запись прошла, `fields=3` | адрес доступен на запись |
| `after=(0.600,...)` | значение легло |
| `reverts=0` | движок его НЕ откатывает |

Если поле пишется, держится и никого не волнует — значит проблема не в поле.

## Причина

Адрес из лога — `0x10DD0060`. Сверка со всеми девятью дампами в `uploads/`:

```
0x10DD0060   uEm8000    <- сюда шла запись
0x10DD7320   uEm0100    <- гоблин
```

`uEm8000` — лагерные существа с `gid 0x61`, их в мире **шесть**.
`uEm0100` — гоблин, он **один** и в списке идёт вторым.

Виновник — `DevTools::FirstEnemyBody()`:

```cpp
if (k[0]=='u' && k[1]=='E' && k[2]=='m') return g_act[i].ptr;
```

«Первый попавшийся `uEm*`». Из семи акторов шесть — зайцы.
Гоблин не был первым **ни в одном** из девяти дампов.

Вторая ошибка в той же функции `Tick()`:

```cpp
const EntityCfg::Tuning& t = EntityCfg::For(100);   // конфиг гоблина...
```

...применялся к тому телу, которое вернул `FirstEnemyBody()`. То есть
настройки `[em0100]` уходили зайцу.

**Мы всё это время масштабировали зайца за двести метров от камеры.**
Поле `+0x60/64/68` при этом, судя по всему, рабочее — просто некому
было показать результат.

## Что исправлено

1. `DevTools::EnemyBodyAt(idx, &kind)` — перебор врагов по индексу.
2. `DevTools::FirstBodyOfKind("uEm0100")` — адресный поиск вида.
3. `Tick()` обходит **всех** врагов; каждому даётся конфиг **его** вида
   (`EmIdFromKind`: `"uEm0100"` → `100`).
4. Все кнопки-диагностики (`ScanVisionParams`, `ReadCharParam`,
   `DumpSensorWindow`, `ForceScale`) переведены на общий `TargetBody()`:
   целится в гоблина и **всегда пишет в лог, кого именно выбрал**.
5. Новая кнопка `LIST enemies + scale` — печатает весь список врагов
   с их текущим масштабом.

## Побочная находка

Компилятор в харнессе выдал `-Wcomment` на `src/ModPaths.h:26`:

```cpp
// Папка мода: <папка игры>\DDDA_AI_Overhaul\
```

Обратный слэш в конце строки — это склейка строк в C++: **следующая
строка молча становится частью комментария**. Обошлось тем, что там
тоже был комментарий. Окажись там код — он бы исчез из сборки без
единой ошибки. Единственный случай на весь проект, исправлен.

## Правила по итогам

- **Прежде чем объяснять отсутствие эффекта природой поля — проверь,
  тому ли объекту ты пишешь.** Адрес в логе обязан сверяться с дампом.
- **Запись, которая держится (`reverts=0`) и не даёт эффекта, — это
  почти всегда не тот объект**, а не «хитрое поле».
- **«Первый в списке» — не значит «тот, кого видит игрок».** Любая
  функция вида `FirstX()` в мире с разнородными сущностями опасна.
- **Любая запись должна логировать ВИД цели, а не только адрес.**
  Одна строка `uEm8000` в логе сэкономила бы две итерации.

## Что проверять в билде 21

1. `LIST enemies + scale` → в логе список; убедиться, что `uEm0100` есть.
2. `FORCE scale 0.60` → в логе `ForceScale: цель uEm0100 0x10DD7320`.
   Гоблин должен съёжиться **немедленно**.
3. С `allowWrites = on` и `scaleJitter = 0.15` — гоблины разного
   телосложения без перезахода.
