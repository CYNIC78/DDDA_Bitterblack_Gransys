# Анатомия гоблина `em0100`

Всё, что мы вскрыли про одного конкретного врага — гоблина. Файл существует
затем, чтобы это не пришлось искать заново: ни нам, ни другим модерам.

Многое из этого верно и для остальных `uEm*`, но **видоспецифичные смещения
переносить нельзя**: размеры тел различаются (гоблин 29632 B, огр другой),
и то, что у гоблина лежит по `+0x5F30`, у химеры лежит неизвестно где.
Универсальное помечено отдельно.

Источники: дампы файлов (`.lmt`, `.rst`, `.prp`, `.sn2`), рантайм-разведка
через DTI и покадровые замеры. Что не подтверждено — так и написано.

---

## 1. Идентичность

**Варианты вида в живом мире.** Скан 19.08 показал в одной стае три
разных DTI-имени: `uEm0100`, `uEm0100_0`, `uEm0100_3`. То есть у гоблина
есть подвиды-варианты как отдельные классы, и фильтр по точному имени
`uEm0100` половину стаи пропустит. Везде, где проверяется вид, сравнение
должно быть по префиксу.


| | |
|---|---|
| Класс | `uEm0100` |
| Размер тела | **29632 B** (`0x73C0`) |
| gid / typeId | `0x00` в поле `+0x2D` |
| Варианты | `uEm0101` (хобгоблин), `uEm0102` (гримгоблин) — те же 29632 B |

**Опознавать только через DTI.** Байт `+0x2D` не уникален: `uEm8000`
(лагерный заяц) носит `0x61`, и попытка маппить по нему ломает Григори.
Фабричные vtable из `types.tsv` с живыми объектами НЕ совпадают — у живого
объекта instance-vtable, единого сдвига нет.

## 2. Поля тела

### Универсальные (проверены на игроке, пешке и врагах)

| Смещение | Тип | Что это |
|---|---|---|
| `+0x0C` / `+0x10` | ptr | связный список живых объектов (next / prev) |
| `+0x2D` | u8 | gid / тип |
| `+0x40` / `+0x44` / `+0x48` | f32 | координаты X / Y / Z в мире |
| `+0x2DC8` | ptr | объект текущего действия (`cEm0100Act*`) |
| `+0x2E64` | ptr | `cAICtrl` — корень AI |

Координаты — те самые поля, в которые движок пишет результат применения
движения. Через них же опознаётся код перемещения (см. `SOURCE_OF_TRUTH` §7.1).

### Видоспецифичные для гоблина

| Смещение | Что это | Статус |
|---|---|---|
| `+0x60` / `+0x64` / `+0x68` | рабочие множители трансформации (W/H/D) | **не настройка**: движок пишет туда каждый кадр (squash&stretch, дыхание, отдача) |
| **`+0x0EE4`…`+0x0EF4`** | **ряд из пяти множителей скорости воспроизведения анимации** | в норме 1.0 каждый; торпор ставит 0.5; запись 0.5 в любой из них замедляет существо вдвое — **подтверждено записью** |
| `+0x2DC0` | `cActionManager::cActBank` (36 B) | менеджер действий |
| `+0x2DE8` | второй указатель на текущий act | дублирует `+0x2DC8` |
| `+0x5870` / `+0x59B0` | копии `cCharParamEnemy` (0x140 B) | найдены по сигнатуре; **все 72 поля подписаны** — см. `src/CharParamEnemy.Generated.h` и `docs/STATUS_EFFECTS_RECON.md` |
| `+0x58C0` / `+0x5A00` | `res_TORPOR` (耐のろま) | сопротивление торпору, у гоблина 1000.0 |
| `+0x5990`…`+0x5998` | `RESTRAINT_SLOW_LV1/LV2/EX` | множители замедления при захвате; в файле 1.0, в рантайме обнуляются движком |
| `+0x73BF` | читаемость = признак «толстого» тела 29 КБ | эвристика |

### Банк таймеров `+0x5F30…+0x5F9C`

Замер в движении вскрыл целую гряду счётчиков рядом:

| Смещение | Период, кадров | Секунд |
|---|---:|---:|
| `+0x5F54` | 4.5 | 0.15 |
| `+0x5F9C` | 5.0 | 0.17 |
| `+0x5F50` | 7.5 | 0.25 |
| `+0x5F58` | 10.5 | 0.35 |
| `+0x5F8C` | 14.6 | 0.49 |
| `+0x5F30` | 29.6 | 0.99 |

Похоже на набор периодических таймеров разной частоты, а не на анимацию.

### Таймеры (подтверждены покадровым замером, гоблин в покое)

Считаются в кадрах анимации: игра тикает 30 раз в секунду.

| Смещение | Период | Секунд |
|---|---:|---:|
| `+0x5F8C` | 14.5 | 0.48 |
| `+0x5F30` | 29.5 | 1.00 |
| `+0x03CC`, `+0x03D0`, `+0x03E4`, `+0x03E8` | ~90 | 3.00 |
| `+0x2DE0` | 119.5 | 4.00 |

Ровные периоды — признак таймера, а не проигрывания анимации: настоящие
длительности неровные (см. §4). `+0x2DE0` лежит внутри области действий
(`0x2DC0…0x2DE8`), похоже на таймаут действия.

## 3. Подобъекты тела

Получено обходом указателей с резолвом имён через DTI. Размеры — из атласа
типов; **это важно**: `cActBank` занимает 36 байт, и всё, что «видно» за
этой границей, принадлежит соседям по куче, а не ему.

| Смещение | Класс | Размер | Назначение |
|---|---|---:|---|
| `+0x0364` | `uModel::Joint` | 160 B | скелет; за ним 4 × `uConstraint::cConstraint` |
| `+0x0FB0`, `+0x0FB4` | `cEfcMotSync` | 12 B | синхронизация эффектов с движением |
| `+0x1028` | `rSoundMotionSe` | 136 B | звук, привязанный к движению |
| `+0x105C` | `rSoundAttributeSe` | | звуковые атрибуты |
| `+0x1C20`, `+0x1C24`, `+0x1C28` | `MtArray` | | три перекрёстно ссылающихся массива |
| `+0x1EF4` | `rRagdoll` | | тряпичная кукла |
| `+0x1EFC` | `uRagdollExt` | | расширение рагдолла |
| `+0x1F18` | `cRigidBody` | | физика |
| `+0x1F80` | `cJointEx` | 24 B | сустав |
| `+0x20F4` | `cGroupParam` | | параметры группы |
| `+0x2110` | `rSoundRequest` | | запрос звука |
| `+0x2710` | `rStatusParam` | | статусы |
| `+0x29AC` | `rShlParamList` | | список параметров shl |
| `+0x2DC0` | `cActionManager::cActBank` | 36 B | менеджер действий |
| `+0x2DC8` | `cEm0100Act*` | 120 B | текущее действие |
| `+0x2E64` | `cAICtrl` | 704 B | корень AI |
| `+0x2E70` | `cNeck` | | шея |
| `+0x5D24` | `uCnsShake` | | тряска |
| `+0x5E7C` | `uEnemy::ScarDataSet` | | шрамы |
| `+0x6074` | `rModel` | 560 B | ресурс модели |

Указатели на `uPlayer` (`+0x2B98`, `+0x5CA4`, `+0x6234`) — ссылки на игрока,
не потомки.

## 4. Анимации (`.lmt`)

Пять наборов, всего 237 анимаций:

| Файл | Анимаций | Смысл |
|---|---:|---|
| `e0100_at.lmt` | 26 | атаки |
| `e0100_co.lmt` | 101 | общие/боевые |
| `e0100_dm.lmt` | 67 | получение урона |
| `e0100_ex.lmt` | 34 | особые |
| `e0100_pl.lmt` | 1 | захват игрока (71 кость против 27) |

Атаки, при 30 кадрах в секунду:

| Длительность | Штук | Примеры (id / кадров / секунд) |
|---|---:|---|
| ≤ 0.7 с | 4 | 26 / 15 / 0.50 · 10 / 19 / 0.63 · 7 / 20 / 0.67 · 16 / 21 / 0.70 |
| 0.9–2.7 с | 17 | 20 / 27 / 0.90 · 1 / 80 / 2.67 |
| ≥ 4 с | 5 | 22 / 143 / 4.77 · 62 / 159 / 5.30 · 48 / 209 / 6.97 |

**Ни одна длительность не даёт круглую секунду.** Это надёжный признак:
если найденный счётчик имеет период ровно 1.00 или 3.00 секунды — это
таймер, а не проигрывание анимации.

### Имена действий и их длительности (замерено в рантайме)

Дамп `.lmt` даёт длительности, но без имён; рантайм даёт имена, но без
длительностей. Хронометраж действий сшивает две половины. Замер: кадры
рендера делятся на два, потому что игра анимирует по 30 в секунду.

**Атаки** (то, ради чего всё раскапывалось):

| Действие | Кадров | Секунд | В `.lmt` | Что это |
|---|---:|---:|---:|---|
| `cEm0100ActNAttack1` | 80.0 | 2.67 | **80** | обычная атака |
| `cEm0100ActNAttack2` | 79.5 | 2.65 | **79** | вторая атака |
| `cEm0100ActNAttack12` | 122.0 | 4.07 | **121** | связка 1→2 |
| `cEm0100ActJumpAttack` | 35.0 | 1.17 | **35** | прыжковый удар дубинкой |
| `cEm0100ActAtckPutWeapon` | 47.0 | 1.57 | **47** | достать оружие |

**Перемещение и повороты**:

| Действие | Кадров | В `.lmt` | Разброс |
|---|---:|---:|---|
| `cEm0100ActTurn90` | 14.7 | **15** | 29..30 стабильно |
| `cEm0100ActTurn180` | 20.8 | **21** | 41..42 стабильно |
| `cEm0100ActDash` | 30.0 | **31** | 60..60 |
| `cEm0100ActDashEnd` | 25.9 | **26** | 51..52 |
| `cEm0100ActRunEnd` | 20.8 | **21** | 41..42 стабильно |
| `cEm0100ActDashTrace` | 22.0 | цикл | 33..73 |
| `cEm0100ActRunTrace` | 66..91 | цикл | 43..421 |
| `cEmActJumpTrace` | 116.5 | — | разгон перед прыжком |
| `cEm0100ActJumpLand` | 99..153 | — | приземление |
| `cEm0100ActRunStumble` | 50.5 | — | спотыкание |

**Простой и социальное**:

| Действие | Кадров | Примечание |
|---|---:|---|
| `cEm0100ActWait` | 243..627 | зависит от обстановки |
| `cEm0100ActWaitCaution` | 90.5 | **91** — настороженное ожидание |
| `cEm0100ActThreatHowl` | 71..402 | угрожающий вой |
| `cEm0100ActFindFinger` | 54.5 | **54** — заметил, тычет пальцем |
| `cEm0100ActHightStart` | 56.0 | — |
| `cEm0100ActFingerLaugh` | 194.5 | насмешка |
| `cEm0100ActHeartyLaugh` | 209.7 | хохот |
| `cEm0100ActPartyDance` | — | танцы у костра: только в группе, в основном ночью |
| `cEm0100ActSitDirection` | — | сидит |

**Пятнадцать совпадений с дампом `.lmt`** — метод подтверждён.

Важное уточнение: `e0100_at.lmt` содержит не только удары. Короткие
анимации на 15 и 21 кадр оказались поворотами (`Turn90`, `Turn180`),
а настоящие атаки длятся 79–121 кадр, потому что включают замах, удар
и восстановление целиком.

**Действия с узким разбросом — фиксированные анимации**, с широким
(`RunTrace` 43..421) — циклы, которые крутятся, пока держится состояние.
`cEm0100ActRunEnd` и `cEm0100ActTurn180` держатся 41–42 кадра всегда:
удобные эталоны для проверки правок темпа.

## 5. Характеристики (`.rst`)

`charparam/em/em0100.rst`, 256 B, четыре записи (normal ×2, hard ×2),
шаг 0x3C:

| Поле | Гоблин | Хобгоблин | Гримгоблин |
|---|---:|---:|---:|
| maxHP | 1000 | 2000 | 6000 |
| сбивание с ног | 100 | | |
| флинч | 100 | | |

HP сверены с вики сообщества — совпадают точно.

## 6. Общие параметры (`.prp`)

`charparam/em/em0100_cmn.prp`, XFS, класс из 72 полей, 320 B. Ключевое:

| Смещение | Поле (яп.) | Смысл |
|---|---|---|
| `+0x00` | 経験値 | опыт |
| `+0x04` | 攻撃力 | атака |
| `+0x08` | 防御力 | защита |
| `+0x14` | 体重 | вес |
| `+0x30`…`+0x98` | 耐* | 30 сопротивлений (огонь, лёд, яд, сон…) |
| `+0x120`…`+0x128` | 拘束スローレート Lv1/Lv2/Ex | замедление при захвате |
| `+0x12C` | スケール値 | масштаб |

**Скорости передвижения в файле нет.** Единственный намёк на темп —
`拘束スローレート`: понятие «rate» у движка есть, но не здесь.

## 7. Сенсоры (`.sn2`)

`AI/Sensor/Enemy/em0100A.sn2`, 416 B. Тройка, найденная в живых объектах:
**1500 / 60 / 3000** — радиус зрения, угол, радиус слуха.

## 8. Чего мы пока не нашли

- ~~**множитель темпа анимации**~~ — **НАЙДЕН 19.08.2026**: ряд
  `+0x0EE4…+0x0EF4`, пять множителей подряд. Путь: у гоблина нет действий
  под のろま, значит торпор замедляет воспроизведение существующих клипов →
  диф по торпору дал наводку → ручная проверка записью выделила ряд.
  В продукте: `[monsterTempo] animEnabled`;
- **часы проигрывания анимации.** В теле только таймеры; в подобъектах
  первого уровня контроллера нет. Кандидаты не исчерпаны: `cEfcMotSync`
  (12 B) и `cActBank` (36 B) слишком малы для состояния, но могут держать
  ссылку на него;
- текущее HP в теле (универсального смещения нет);
- поле темпа атак — задача, ради которой всё это и раскапывалось.

## 9. Как этим пользоваться

Всё перечисленное читается инструментами из репозитория:

```bash
python3 tools/lmt_dump.py  resources/.../e0100_at.lmt     # длительности анимаций
python3 tools/rst_dump.py  resources/.../em0100.rst       # HP и стойкость
python3 tools/xfs_dump.py  resources/.../em0100_cmn.prp   # 72 поля параметров
python3 tools/sn2_dump.py  resources/.../em0100A.sn2      # сенсоры
python3 tools/prp_to_header.py                            # карта cCharParamEnemy -> заголовок
```

В игре: `[devtools] enabled = on` → F12 → DevTools → **List child objects**
для карты подобъектов, **Anim probe** для поиска счётчиков.
