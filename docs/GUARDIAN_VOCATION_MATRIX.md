# Guardian — vocation-aware решение (финальное, 19.08.2026)

## Вывод

Guardian как «доктрина телохранителя» применим ТОЛЬКО к трём мили-вокациям:

```text
✅ Fighter, Warrior            → штурмовик-телохранитель
   (наш фикс: снятие штрафов code 54, градиент preempt/melee, роль Assault/Protector)

⚠️ Strider (гибрид)           → ПОД ВОПРОСОМ
   - ближний бой (кинжалы) — годен как штурмовик;
   - но дальнобойные атаки (лук) — та же проблема, что у лучника (агрит издалека);
   - истинная роль страйдера — ДИВЕРСИОННАЯ/спецназ: вскарабкаться на монстра,
     снять маску/бить в уязвимое место, быстро менять позицию, фланкировать;
   - решение: ЧАСТИЧНЫЙ кордон Guardian + компенсация Pioneer-перевесом
     (туманный кейс, требует A/B в бою).

❌ Mage, Sorcerer, Ranger, Magick Archer → Guardian НЕ юзабелен
   - гвардиан-маг/чародей = нонсенс (кастер не должен прижиматься/бегать хвостом);
   - гвардиан-лучник/чародей тащат агро на игрока (стоят близко + за спиной);
   - Capcom это «предотвратили» штрафами на атаку → гвардиан стал пассивным хвостом.
```

## Что делать по вокациям

```text
мили (Fighter/Warrior):
  - активная Guardian-доктрина (снятие штрафов, перехват в зоне)  [уже сделано]
  - роль: лидер-мили → Assault (вместе бьём); лидер-хилый → Protector (заслон)

гибрид (Strider):
  - ЧАСТИЧНЫЙ кордон Guardian (не душить полностью, но не давать уходить в
    «хвост»-пассивность) + Pioneer-перевес для диверсионной подвижности;
  - требует A/B: как ведёт себя страйдер-гвардиан в бою (кинжалы vs лук).

дальний (Mage/Sorcerer/Ranger/MagickArcher):
  - КОРДОН на Guardian (гасить, не давать дрейфовать вверх);
  - позиционирование через Pioneer-перевес (держать дистанцию, огонь с тыла);
  - Guardian-штрафы оставить vanilla (пассивность тут полезна — не лезь в мили).
```

## Почему именно так (цепочка)

1. Capcom снизили атакующие веса Guardian, чтобы дальнобойщик не тащил агро
   на игрока → побочно сделали Guardian пассивным хвостом.
2. Мы сняли штрафы → мили-гвардиан стал активным штурмовиком (хорошо).
3. Но у дальнобойщика активный Guardian = ВРЕД (агрит и тащит монстра на игрока).
4. Значит: активный Guardian только для мили; дальнобойщику — кордон + Pioneer.

## Рычаги (что доказано)

- Дистанция удержания считается в коде цели Follow (runtime-поля нет).
- Единственный рабочий рычаг дистанции = веса склонностей (Pioneer vs Guardian).
- Точный контроль позиции (заслон/сбоку/дистанция) — требует RE цели Follow
  (отдельная задача, не сейчас).

## Статус реализации

- Снятие штрафов + градиент + роль (Assault/Protector) — СДЕЛАНО (Build 57-63).
- Vocation-aware кордон (гасить Guardian для дальних вокаций) — **СДЕЛАНО
  (Build 73.13)**: `src/pawnai/VocationCordon.{h,cpp}`.
- Strider: частичный кордон + Pioneer-перевес — **СДЕЛАНО**, значения по
  умолчанию мягче, чем у дальних (cap 550 против 300). Требует A/B в бою.
- Pioneer-перевес для дальнобойщиков — **СДЕЛАНО** (пол склонности).

### Как именно сделан кордон (73.13)

Кордон задаёт **потолок** склонности, а не вычитает число: если игрок и
так держит Guardian ниже потолка, модуль молчит. Так он предсказуемо
складывается с ползунками и с ситуативными надбавками других модулей —
и поэтому в оркестраторе стоит последним.

| Класс вокации | Guardian cap | Pioneer floor |
|---|---:|---:|
| мили (Fighter / Warrior / Mystic Knight) | не трогаем | не трогаем |
| гибрид (Strider / Assassin) | 550 | 550 |
| дальний (Ranger / Magick Archer / Mage / Sorcerer) | 300 | 650 |

Все четыре числа — ползунки в панели и ключи ini (`[pawnAI] cordon*`).

### Что в Guardian всё ещё НЕ закрыто

1. **Коды меча и двуручника.** Главный рычаг доктрины — снятие Guardian-штрафа
   с наступательного интента — работает только для кинжалов (`code 54`).
   Для Файтера и Варриора нужный код ещё не пойман: требуется аудит с
   пешкой соответствующей вокации. До этого мили-Файтер получает от
   доктрины роль и градиент, но не снятие штрафа.
2. **Точное позиционирование.** «Встань на фланг, стреляй из тыла» через
   склонности не выражается. Pioneer — это «не липни к якорю», не более.
   Нужен реверс цели Follow.
3. **Наёмные пешки.** Кордон и доктрина работают по главной пешке:
   остальные в разборе партии пока не различаются.

## Коды намерений по оружию (Build 73.27)

Дыра «главный рычаг работает только для кинжалов» закрыта наполовину:
недостающие коды теперь известны. Источник — таблица
`docs/generated/PAWN_GOAL_CODES.md`, где номер слота ресурса цели и есть код
приоритета (обоснование — `docs/PAWN_SPRINT_RECON.md` §25).

| код | цель | вокации | смещение измерено? |
|----:|------|---------|--------------------|
| 52 | `WpnSwordAtk` | Fighter, Mystic Knight, Assassin (меч) | нет |
| 53 | `WpnGSwordAtk` | Warrior, Fighter (двуручник) | нет |
| 54 | `WpnDaggerAtk` | Strider, Ranger, Assassin (кинжалы) | **да, −3** |
| 55 | `WpnWandAtk` | Mage, Sorcerer (посох) | нет |
| 56 | `WpnShieldAtk` | Fighter, Mystic Knight (щит) | нет |
| 57 | `WpnBowAtk2` | Strider, Ranger (лук), из `tu2` | нет |

Столбец «смещение измерено» — граница честности. Таблицу правил Guardian мы
читали только для кода 54. Для остальных известен **номер**, но не штатное
значение штрафа, а рычаг без известного исходного значения писать нельзя:
нечего будет откатывать и не с чем сравнивать.

**Что нужно, чтобы закрыть вторую половину:** пешка-Файтер в городе, дамп
правил приоритета, сверка кодов 52/53 с этой таблицей. Ровно тот аудит,
который и так стоял в плане, — но теперь известно, какие числа в нём искать.

Заодно уточнено по той же таблице:

* код 13 — `Recovery` (раньше стоял как «party relation, HYPOTHESIS»);
* коды 4 и 66 в наборе тестовой пешки **пусты**: их слоты нулевые, значит имя
  им может дать только пешка другой вокации. Прежние догадки «wait/follow
  response» и «battle response» сняты как безосновательные.
