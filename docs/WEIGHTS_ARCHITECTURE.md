# Архитектура весов инклинаций (v3.0) — «якорь + дельта + оверрайд»

**Статус:** 15.08.2026. Заменила «пресеты + кастомный пресет 6» (рождённые на коленке).
**Почему:** старый UI обманывал игрока — ползунок не работал, когда был выбран пресет.
**Север:** ползунки — истина. Пресет — снапшот, кнопка «загрузить в ползунки».

---

## 1. Три слоя

```
┌────────────────────────────────────────────────────────────┐
│  ОVERRIDE (кризис) — EmergencyOverrider                     │
│  finalTarget = профиль спасения (игрок упал и т.п.)         │
│  Приоритет максимальный. Кордон МОЛЧИТ.                    │
├────────────────────────────────────────────────────────────┤
│  DELTA (бой) — модули возвращают поправки                  │
│  SmartUtil:      перелив Utilitarian ↔ Scather/Challenger   │
│  TacticalSwitch: категория врага → сдвиг весов              │
│  (будущее) TargetScan: «волк целится в игрока» → защита     │
├────────────────────────────────────────────────────────────┤
│  BASE (всегда) — anchor[], ползунки игрока                 │
│  Пресеты только ЗАГРУЖАЮТСЯ в anchor[].                    │
│  Санкордон: фильтрует ЦЕЛЬ (жмёт мусор до капа), не значения│
└────────────────────────────────────────────────────────────┘

finalTarget = (overrideArmed) ? override : clamp(anchor + Σ delta)
один лерп:   incl[i] += (finalTarget[i] - incl[i]) * smooth
```

### Ключевое правило

**Модули не пишут в `incl[]` и не трогают ползунки.** Они возвращают `delta[]`,
оркестратор складывает и делает ОДИН лерп. Никакой драки между модулями:
порядок вызовов больше не влияет на результат, всё композируется аддитивно.

## 2. Что стало с «мусорными» инклинациями

Guardian/Nexus/Acquisitor **не мусор — они ситуативные**:

| Инклинация | Плохо | Хорошо |
|---|---|---|
| Guardian | праймари ВСЕГДА → балласт на хвосте | в кризисе: пешка рвётся к упавшему игроку |
| Nexus | праймари ВСЕГДА → стадо без воли | пешка упала → остальные спасают товарища |
| Acquisitor | праймари → собиратель, а не боец | исследование после боя / вне боя |

Санкордон режет их **в покое** (фильтрует цель), но **молчит в кризисе**
(override-режим: оркестратор просто не вызывает ApplyCap).

## 3. Интуитивность для игрока

- Ползунки ВСЕГДА активны. Сдвинул — цель изменилась. Точка.
- Кнопка пресета = «переезд» ползунков на его значения.
- Индикатор `(Modified)` — ползунки отошли от последнего загруженного пресета.
- В бою справа от ползунка видно `Live: 780 (+150)` — база игрока + дельта системы.
  Игрок ВИДИТ, что система делает, и может отключить (`Auto-adapt in combat`).

### Контракт модуля (для разработчика)

```cpp
void MyModule::GetDelta(const float* base, float* delta);
// base  — текущая цель (anchor + накопленные дельты), только для контекста
// delta — твоя поправка, СЛОЖИСЬ, не затирай (delta[i] += ...)
```

Добавить новый источник поведения = написать модуль с GetDelta + вписать
`SAFE_MODULE(module, GetDelta(target, delta))` в оркестратор. Падение модуля
отключает только его (SEH), остальные продолжают работать.

## 4. Расширяемость: что придёт после реверса таргетов

Когда раскопаем target-сущностей (на кого смотрит/целится враг), это станет
**ещё одним источником delta** — без изменения контракта:

| Источник | Вход | Дельта (пример) |
|---|---|---|
| TacticalSwitch (есть) | категория врага | Scather/Challenger по типу |
| SmartUtil (есть) | знание (mStudyFlag) | Utilitarian ↔ боевые |
| **TargetScan (будущее)** | волк целится в игрока | +Guardian (спаси), +Mitigator (бей толпу у игрока) |
| **SitRep (будущее)** | игрок упал, враги рядом | OVERRIDE — профиль спасения |
| **ThreatAssess (будущее)** | N врагов на игрока | градиент: чем больше ганк, тем сильнее защита |

Иерархия приоритетов уже заложена: **override > base + delta > кордон**.
TargetScan — просто ещё один `SAFE_MODULE` в цепочке. Контракт не меняется.

## 5. Миграция ini (мягкая, старые ключи читаются)

```
Было:  [pawnAI] preset = 5            → больше не «режим»
       [customAnchor] scather = 750   → остаётся ключом-якорем
Стало: [pawnAI] lastPreset = Balanced → индикатор Modified
       [customAnchor] ...             → те же якоря
```

`LoadConfig()` читает `[customAnchor]` поверх дефолта Balanced.
`SaveConfig()` пишет якоря + lastPreset + smooth.
