# Почему система «не видела» волков и бандитов

## Диагноз: дело было не в классификации

Первая мысль — «надо добавить волка в список видов». Неверно.
Волки и бандиты **вообще не попадали в список акторов**.

Поиск тел в куче (`PollSeedSlice`) принимал кандидата только через
`IsSeedVt()`:

```cpp
static int IsSeedVt(uint32_t val)
{
    return val == kGoblinInst || val == kEm8000Inst
        || val == kNpcInst || val == kUnk84Inst || val == kHareInst;
}
```

Пять захардкоженных instance-vtable. Всё остальное отсеивалось на входе.
Волк, бандит, огр не становились «семенем», значит `DumpActorsFrom` их
не обходил, значит их не было ни в счётчике, ни в мутациях.

Вторая половина той же проблемы — присвоение имени:

```cpp
if (A.vt == kGoblinInst) A.kind = "uEm0100";
else if (A.vt == kNpcInst) A.kind = "uNpc";
...
else A.kind = "?";
```

Даже если бы тело как-то попало в список, оно получило бы `kind = "?"`.

**Список констант не масштабируется.** Видов в игре 35+, у каждого своя
instance-vtable, которую надо поймать в бою и записать вручную. Так мы
ловили гоблина неделю.

## Решение: спрашивать имя у игры

У нас уже есть `NameOfLiveObject()` — DTI-резолвер:

```
объект -> [0] vtable -> GetDTI() -> DTI+4 = char* имя класса
```

Тот же приём, которым определяется состояние смерти. Он не зависит от
таблиц и работает для **любого** типа сразу.

Теперь `LooksLikeCreatureAt(obj, vt)`:

1. `LooksLikeVtable(vt)` — дешёвая проверка;
2. читается `+0x2D` (gid) и `+0x40` (координата X) — у всех тел они есть;
3. `NameOfLiveObject` → имя;
4. `uEm*` или `uHumanEnemy` → это существо.

Известные пять vtable оставлены как **быстрый путь**: для них имя
статическое, без чтения памяти. DTI-разбор идёт только для незнакомых,
и только если значение вообще указывает в образ (`InImage`) — иначе мы
разбирали бы vtable у каждого случайного числа в куче.

## Вторая правка: заяц — не враг

Наблюдение пользователя: «зайцы-драконы определяются как враги, они не
угроза».

Верно. `uEm8000` — шесть тел вокруг стоянки, они прибавляли +6 к счётчику
опасности на пустом месте. Разделено на три понятия:

| функция | что значит | кто входит |
|---|---|---|
| `KindIsCreature` | можем управлять | `uEm*` + `uHumanEnemy` |
| `KindIsHarmless` | не угроза | `uEm8000`, `uEm8600` (Hare) |
| `KindIsEnemy` | угроза | creature, но не harmless |

Важно, что это **разные** вопросы:

- **масштабировать** зайца можно и нужно — разнообразие живности;
- **считать угрозой** нельзя.

Поэтому перебор для мутаций (`EnemyBodyAt`, `FirstEnemyBody`) идёт по
`KindIsCreature`, а счётчик опасности (`EnemyCount`, `enemyCount` в
`WorldReport`) — по `KindIsEnemy`.

`DeadCount` считает трупы всех существ: труп зайца тоже лежит на земле,
цифра должна сходиться с тем, что видит игрок.

В `WorldReport` добавлен `critterCount` — безобидные отдельной строкой.

## Напоминание из FIELD_MAP

`uEm8000` — **не Григори**. Маппить gid `0x61` → Hare в `BestiaryData.h`
запрещено, это сломает Григори. `uEm8000` и `uEm8600` — разные виды,
оба попадают в «безобидные», но по имени класса, а не по gid.

## Что проверить в игре

1. **Волки** — теперь должны появляться в списке и в `enemies`.
2. **Бандиты** (`uHumanEnemy`) — то же самое.
3. **Зайцы** — в `critters`, НЕ в `enemies`.
4. Счётчик `units` должен включать всех, `enemies` — только угрозы.

Если волк по-прежнему не виден, значит его тело лежит вне горячего
кольца `0x10000000..0x18000000`, и надо расширять диапазон поиска —
это уже другая задача.

## Цена

DTI-разбор на незнакомых указателях дороже сравнения с константой, но:

- вызывается только для значений, указывающих в образ игры;
- поиск ограничен бюджетом 4 МБ за тик (8 МБ при пустом списке);
- у найденных тел путь всё равно быстрый (кеш `g_actSlotOff`).

Просадок ждать не стоит, но если появятся — первым делом смотреть сюда.
