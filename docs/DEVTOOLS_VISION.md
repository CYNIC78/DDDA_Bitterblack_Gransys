# DevTools Vision — карта типов, живой мир, консоль

**Статус:** 13.08.2026. Фаза 0.4 закрыта (dump18–24). Фаза 0.6 в поле: dump24, zip 30, полл закрыт. Выгрузка = гистерезис движка. [`ROADMAP.md`](ROADMAP.md).
**Для кого:** команда. Это не фича в F12 для игрока. Это глаза продукта. Без них CombatIntel навсегда останется рефлексом на боль.

> Короткий вердикт: проблема реальная, диагноз чуть не тот.
> Нам не хватает не «ещё адресов». Нам не хватает **моста** между уже существующим реестром типов (`types.tsv`, 4405 фабрик) и живыми объектами на куче.
> Консоль как в Скайриме — правильная *потребность*, неправильная *метафора*.
> Произвольный спавн — не «нет», и не «да, PlaceAtMe». Это отдельный исследовательский трек через пайплайн самой игры.

## 1. Что мы на самом деле ищем вслепую

Каждая новая фича сейчас выглядит так:

1. Нужен yaw / HP / менеджер / флаг квеста.
2. CE: scan → changed/unchanged → dissect → сигнатура.
3. Хардкод оффсета или хука.
4. Краш на загрузке / другой сборке / другом типе врага.
5. Повтор.

Так родились `pBase+0xA7000`, `mStudyFlag+0x1616`, `DDDA.exe+374739`, TargetLock с `Alt+X` «захвати физику», CameraPlus с двумя сигнатурами камеры. Это работает. Это не масштабируется.

Стена `types.tsv` уже пробита 10.08 — но только для **идентификации врага после удара**. Level 3 из `TYPES_TSV_WALL_BREAKTHROUGH.md` («live scan менеджеров») так и остался абзацем в доке. CombatIntel по-прежнему слепой, пока кто-то не получит урон.

Две разные дыры смешались в одну жалобу:

| Дыра | Что это | Можно ли «замапить навсегда» |
|---|---|---|
| **Тип** | «что это за класс» — имя, vtable, sizeof, factory, TypeId | **Да.** Это `types.tsv`. Адреса стабильные RVA. |
| **Экземпляр** | «где сейчас этот гоблин / камера / sEnemyManager» | **Нет.** Куча, перезагрузка зоны, ASLR. Ищется через тип. |

Мы пытаемся CE-сканом закрывать дыру №2, каждый раз заново открывая дыру №1. Карта адресов, которую стоит оставить людям — это карта **типов + полей**, не карта абсолютных указателей.

## 2. Что `types.tsv` уже даёт — и что мы из него не берём

Источник: [Atvaark/DragonsDogma.Research](https://github.com/Atvaark/DragonsDogma.Research). 4405 вызовов `register_type_factory` внутри `DDDA.exe`. VA под базу `0x400000`.

Колонки (заголовок Atvaark врёт, проверено у нас и скриптом `rename_type_factories.py`):

| # | Реально | Зачем |
|---|---|---|
| 0 | Caller | `call` регистрации — якорь в коде |
| 1 | FactoryPointer | глобал фабрики в `.data` |
| 2 | FactoryName | `uEm0500`, `sEnemyManager`, `uPlayer`… |
| 3 | Allocator | какой кучей объект живёт |
| 4 | Size | `sizeof` — граница дампа, анти-краш |
| 5 | TypeId | у врагов == `targetBase[0x2D]` == наш `groupId`. У 4295 типов = 0 |
| 8 | ResetFactoryFunc | сброс фабрики |
| 9 | FactoryVtable | vtable **фабрики**, не инстанса |

Важнее, чем колонки: IDA-скрипт Atvaark из первой функции фабричного vtable делает имя `create_uEm0500`. То есть у **каждого** из 4405 типов есть нативная функция создания. Это не Skyrim `PlaceAtMe`, но это и не ноль.

Сейчас генератор вытаскивает **110** записей (`uEm*` с TypeId ≠ 0 + два ручных). В TSV при этом:

- **149** `uEm*` (39 подтипов/частей с TypeId=0: `uEm0100_0`, тентакли голема, базы `uEmWolfBase`…)
- **74** `cSetInfoEnemy*` — дескрипторы постановки в мир
- **21** синглтон-менеджер (`sEnemyManager`, `sSetManager`, `sUnit`, …)
- **305** AI/FSM/Think классов
- **47** камерных типов
- **uPlayer** size `23056`, vt `0x15E4F34` → RVA `0x11E4F34` — тот самый, что уже захардкожен в `IsPartyMember`

Мы сидим на полном RTTI-заменителе MT Framework и пользуемся им как таблицей гоблинов.

### Префиксы MT Framework — читать имена вслух

| Префикс | Смысл | Пример |
|---|---|---|
| `s` | singleton, один на процесс | `sEnemyManager`, `sUnit`, `sSetManager` |
| `u` | unit, живой объект в мире | `uEm0100`, `uPlayer`, `uCameraGame` |
| `c` | component / param / act | `cSetInfoEnemy0100`, `cThinkMgr`, `cLayoutSetEnemy` |
| `r` | resource (из .arc) | модели, лоты, FSM |
| `a` | application | `aGameMain` |
| `Mt` | ядро движка | `MtObject` (корень; `*(void**)obj` = vtable) |

Любой живой `MtObject` опознаётся так:

```cpp
uintptr_t base = (uintptr_t)GetModuleHandle(nullptr);
uint32_t  rva  = *(uintptr_t*)ptr - base;
const TypeInfo* t = FindByVTable(rva);   // O(1) после хеш-таблицы
// t->name, t->size, t->typeId, t->factoryRVA
```

Это уже написано для 110 врагов. Нужно для 4405 типов.

## 3. Консоль как в Скайриме — где аналогия ломается

Сообщества 2016–2023: **розничный DDDA не имеет консоли**. Ни `~`, ни `player.placeatme`. То, что иногда принимают за консоль (Ctrl+Shift+Tab), к спавну не относится.

Скайрим может спавнить что угодно, потому что:

- у каждой сущности есть `FormID` / `ActorBase`;
- движок data-driven: данные отделены от кода;
- `PlaceAtMe` — публичный пайплайн, которым пользуется сама игра.

DDDA / MT Framework — **layout-driven**:

```
stageXXX.arc
  └─ LOT (кто, где, сколько)
       └─ rLayoutGroupParamList (.gpl)  ← белый список типов на зону
            └─ sSetManager::cLotMgr<cLayoutSetEnemy>
                 └─ cLayoutSetEnemy / cSetInfoEnemyXXXX
                      └─ create_uEmXXXX()          ← factory vtable[0]
                           └─ sArchiveManager грузит emXXXX.arc
                                └─ cThinkMgr + FSM + navmesh
                                     └─ объект попадает в sUnit / sEnemyManager
```

FluffyQuack (2016, туториал по LOT): дублировать запись в LOT — враг появляется. Поменять тип на «чужой» для зоны — часто **ничего не спавнится**. Причина, которую он сам подозревал: `.gpl`. Плюс лимит одновременно живых врагов (~10 активных из 30 поставленных). Плюс у stage100 три копии одного LOT (`st100_*`, `*_lot`, `*_sub`).

Поле dump24 это подтверждает с нашей стороны: World держит 10–15 смешанных тел; дальние LOT не инстанциируются; выгрузка гистерезисная (сотни метров + LOS, тушки пляшут на экране). Не писать свой despawn. Кап ~10 — оценка, не константа в коде.

Следствие: `spawn goblin` в консоли — это не `new uEm0100`. Это «прокрутить кусок пайплайна, которым игра сама ставит гоблина», плюс убедиться что `em0100.arc` уже в `sArchiveManager` и тип не режет GPL.

DD2 делает Enemy Spawner через REFramework, потому что RE Engine отдаёт DTI и Lua. У нас DTI есть внутри процесса (`MtObject` / фабрики), наружу не торчит. Мы строим **бедный REFramework для MT Framework**. Это и есть правильное имя инструмента, не «скайримовская консоль».

## 4. Спавн: честный вердикт

| Сценарий | Оценка | Почему |
|---|---|---|
| Заменить волка на варга в том же LOT (Nightmare) | 🟢 реально | тип родственный, arc/GPL часто уже готовы |
| Доспавнить ещё одного гоблина в лагере гоблинов | 🟢 реально | arc загружен, пайплайн тёплый |
| `spawn uEm0100` рядом с ГГ в Грансисе | 🟡 реально после реверса | Грансис уже держит гоблинов; надо вызвать пайплайн, не `new` |
| `spawn uEm7002` (Daimon) в Кассардисе | 🔴 упадёт или пустышка | нет `em7002.arc`, нет think/FSM, нет арены |
| `spawn` любого из 149 uEm в любой точке | 🔴 не цель DevTools v1 | это загрузчик ресурсов + navmesh + GPL bypass |
| Подменить emId в момент чтения LOT (динамический Nightmare) | 🟡 средний | не спавн «из воздуха», а хук существующего спавна |

Четыре пути, от дешёвого к святому граалю:

1. **Статический LOT** — уже в роадмапе Фазы 2/3. Надёжно, нужен рестарт. Для Nightmare это основной путь.
2. **Респавн существующей постановки** — ткнуть флаги `cThinkFSMParamLotFlag` / save-unit в `sSetManager`. Враг, которого зона уже знает, встаёт снова. Для тестов AI — часто достаточно.
3. **Повтор нативного `create_*`** — хук `create_uEm*` и `cLayoutSetEnemy` на *естественном* спавне, лог аргументов и стека, потом replay из консоли. Это единственный честный путь к `spawn goblin`.
4. **Голый `new` + конструктор** — почти наверняка краш. Нет регистрации в `sUnit`, нет модели, нет AI. Не делаем.

Для разработки PawnAI/CombatIntel/TacticalSwitch спавн «любого босса под ноги» — роскошь. Нужнее **видеть, кто уже в комнате**, не дожидаясь удара.

## 5. Как я вижу инструмент

Три слоя. Каждый сам по себе полезен. Вместе это DevTools.

```
┌──────────────────────────────────────────────────────────┐
│  DevConsole  (F11, ini [devtools], не путать с F12)      │
│  help / type / inspect / list / watch / pause / weather  │
│  spawn — только после трека 4.3                          │
└────────────────────────────▲─────────────────────────────┘
                             │
┌────────────────────────────┴─────────────────────────────┐
│  WorldScan                                                │
│  sEnemyManager / sHumanEnemyManager / sNpcManager         │
│  sPawnManager / sPlayerManager / sSetManager / sUnit      │
│  → список живых u* без урона → CombatBus                  │
└────────────────────────────▲─────────────────────────────┘
                             │
┌────────────────────────────┴─────────────────────────────┐
│  TypeAtlas  (4405 имён, RVA, size, TypeId, factory)       │
│  Identify(ptr) / FindByName / FindByVTable                │
│  + FieldMap: разведанные оффсеты по имени типа            │
└──────────────────────────────────────────────────────────┘
```

Релиз игроку: atlas врагов как сейчас + CombatIntel. DevTools за `ini` и `#ifdef`, чтобы не размыть «это не чит-мод».

### 5.1 TypeAtlas — карта, которую оставляем людям

Генератор (расширение `tools/generate_bestiary.py` или отдельный `tools/generate_type_atlas.py`):

- `src/TypeAtlas.Generated.h` — компактный массив + хеш по vtableRVA и по имени.
- `docs/TYPE_ATLAS.md` — человекочитаемый каталог: менеджеры, пайплайн спавна, игрок/пешки/камера, все `uEm*`, все `cSetInfoEnemy*`.
- `docs/FIELD_MAP.md` — растёт руками: `uPlayer+0xDD0 = level`, `uEm*+0x2D = TypeId`, HP в сабобъекте `+0x8`, инклинации, `mStudyFlag`. Это и есть «рабочая мапа адресов».

Не тащим 341 КБ TSV в релиз. В Dev-сборке строки 4405 имён — копейки.

### 5.2 WorldScan — перестаём ждать удар

Первый эксперимент в игре (полчаса у CE/лога, закрывает неделю гаданий):

```text
base = GetModuleHandle(NULL)
fp   = base + (FactoryPointer - 0x400000)     // для sEnemyManager: 0x1986EA0

проверка A:  *(void**)fp  == vtable sEnemyManager ?  → fp сам синглтон
проверка B:  **(void***)fp == vtable                ?  → fp это **instance
проверка C:  *fp выглядит как factory object
             (первый dword == FactoryVtable),
             а синглтон рядом в .data                 → ищем соседа
```

Прогнать на `sEnemyManager`, `sPlayerManager`, `sWeatherManager` (погоду мы уже пишем через `pBase+0xB8780` — сверка), `sUnit`. Результат записываем в FIELD_MAP: «синглтоны резолвятся так». Дальше массив врагов — dissect одного менеджера, не 110 CE-сканов.

`sUnit` весит **1 700 720 байт**. Это главный список юнитов движка. `sNpcManager` — 295 008. `sSetManager` — 112 976 (лоты). `sQuestManager` — 132 096. Размеры сами подсказывают, где лежат массивы.

Когда сканер живой:

- TacticalSwitch видит грифона *до* первого хита.
- TargetLock берёт yaw с объекта, а не с `Alt+X`.
- CombatIntel по-прежнему врёт на зайце после удара (gid `0x61` → Dragon). Бандит закрыт (`0xE0` по vtable). Dump20: 6× live `[0]=0x015BB278` kind `uEm8000`. WorldReport **не** публикует их как кат. 5. Identity = instance vt + цепь `+0C`, не gid. Чинить `FindEnemyByGid(0x61)` нельзя.
- Nightmare может смотреть, какой `cLayoutSetEnemy` сейчас активен.

### 5.3 DevConsole — «вызвал команду, она выполнилась»

Не парсер Oblivion. ImGui-окно + строка + история. Команды = тонкие обёртки над тем, что уже умеем, плюс atlas/scan.

**Сразу, без нового реверса**

| Команда | Опора |
|---|---|
| `help`, `type uEm0500`, `type sEnemyManager` | TypeAtlas |
| `inspect 0xADDR` | Identify + hexdump в пределах `size` |
| `list types uEm` / `list types s` | фильтр атласа |
| `list enemies` | WorldScan, либо пока ring buffer |
| `pause`, `timescale` | CameraPlus |
| `weather`, `night` | Nightmare / `pBase+0xB8780` |
| `cam freeze/fly` | CameraPlus F4 |
| `watch 0xADDR [size]` | live memory в UI |

**После FieldMap игрока**

| Команда | Опора |
|---|---|
| `tp x y z` / `getpos` | физика ГГ (то, что TargetLock ловит руками) |
| `god`, `heal` | HP-структура, тот же хук `+374739` |
| `inclination` | уже пишем |

**После трека спавна**

| Команда | Опора |
|---|---|
| `respawn` | флаги лота текущей зоны |
| `spawn uEm0100` | replay нативного пайплайна |
| `killall` / `kill near` | HP write по списку сканера |

Консоль — dev-продукт. Если когда-нибудь вынесем в F12, то только `list` / inspect / camera, без god/spawn.

### 5.4 SpawnProbe — исследование, не кнопка

Отдельный модуль, по умолчанию только лог:

- хук `create_uEm*` (взять код из factory vtable);
- хук входа в `cLayoutSetEnemy` / `cSetInfoEnemy*`;
- на естественном спавне писать в `ddda_ai_overhaul.log`: имя типа, args, caller, загружен ли arc.
- через неделю логов будет видно, *какую* функцию консоли вызывать.

Пока этого лога нет — кнопки Spawn в UI нет. Не обещаем игрокам то, чего не вызвали сами.

## 6. Как это ложится на текущий код

Не ломаем шину. Расширяем.

```
TypeAtlas ──Identify──► WorldScan ──Publish WorldReport──► CombatBus
                              │                                │
                              ▼                                ▼
                        DevConsole                        PawnAI modules
                        ObjectInspector                   (SmartUtil, TacticalSwitch, …)
```

`CombatIntel` остаётся тренером по *урону и знанию* (`Publish` → `LastReport`). WorldScan — тренер по *присутствию* (`PublishWorld` → `LastWorld`, zip 27). Каналы раздельные: удар не топчет комнату. TacticalSwitch читает оба; хит побеждает, если уже был. `uEm8000` в world-канале без категории.

Новые файлы (предложение):

```
src/devtools/
  TypeAtlas.h / TypeAtlas.Generated.h
  FieldMap.h                 // оффсеты, которые мы сами разведали
  WorldScan.cpp/.h
  ObjectInspector.cpp/.h
  DevConsole.cpp/.h
  SpawnProbe.cpp/.h          // только лог, пока не созреет
docs/
  DEVTOOLS_VISION.md         // этот файл
  TYPE_ATLAS.md              // генератор
  FIELD_MAP.md               // живой, руками
tools/
  generate_type_atlas.py
```

Сборка: Release остаётся игровым. DevTools включается `[devtools] enabled = on` в ini (по умолчанию off).

## 7. План работ — что режет слепоту быстрее всего

Не «сначала спавн». Сначала зрение.

| Срез | Срок | Выход | Зачем |
|---|---|---|---|
| **A. Atlas** | 1 день | `TypeAtlas.Generated.h` + `TYPE_ATLAS.md` на 4405 | публичная карта; Identify(any) |
| **B. Inspector** | 1–2 дня | F11: адрес → имя типа, size, hexdump | 80% CE-сессий умирают здесь |
| **C. Singleton resolve** | 1 вечер в игре | FIELD_MAP: как достать `sEnemyManager*` | ключ ко всему живому миру |
| **D. WorldScan uEm** | 2–4 дня | `list enemies` без удара, ptr+gid+pos | TacticalSwitch / TargetLock / Nightmare |
| **E. Console v0** | параллельно с B | команды из таблицы 5.3 «сразу» | «вызвал — выполнилось» |
| **F. SpawnProbe** | после D | лог нативных create/layout | решение по spawn, не гадание |
| **G. spawn/respawn** | когда F покажет функцию | одна команда на тёплый тип | тесты AI, не контент-мод |

Срезы A+B+E можно делать без новой игровой сессии. C — единственное, что требует «запусти DDDA и пришли лог». D без C не начинается.

## 8. Риски, которые я не хочу прятать

- **Steam vs GOG.** RVA фабрик привязаны к конкретной сборке. `pBase` мы ищем сигнатурой именно поэтому. Atlas должен всегда считать `base + (VA-0x400000)`. Если GOG-exe другой — либо второй столбец RVA, либо runtime-скан регистрации. Не хардкодить абсолютные VA.
- **vtable ≠ 0 у всех.** Часть баз (`uEmWolfBase`, `uPlayerBase`) в TSV имеет vt `0x15CEF40` — общий заглушечный. Identify по одному vtable будет врать. Второй ключ: TypeId / размер / положение в менеджере.
- **Лимит живых врагов.** Даже идеальный spawn упрётся в то, что нашёл FluffyQuack. Для тестов AI это неважно (нужна одна химера, не тридцать). Для «армии гоблинов» — отдельный реверс лимита в `sEnemyManager`.
- **Краши на загрузке.** Любой обход менеджеров — только после `IsInActiveGameplay()` и `__try`. Сканер не должен жить в DllMain.
- **Идентичность мода.** Spawn/god в публичном F12 превращают нас в второй dinput8-чит. Держим за ini.

## 9. Ответ на исходный вопрос

> «Почему бы не сделать рабочую мапу адресов и нечто вроде консольных команд?»

Нужно. Но мапа — это не Cheat Engine table на 500 абсолютных адресов. Это:

1. **TypeAtlas** — 4405 фабрик, уже лежащих у нас в репо.
2. **FieldMap** — оффсеты полей внутри типа, которые мы сами подтвердили.
3. **WorldScan** — как из фабрики/синглтона достать *текущие* экземпляры.
4. **DevConsole** — человеческий интерфейс к п.1–3 и к хукам, которые уже есть (пауза, камера, погода, урон).

> «А может у нас не получится произвольно спавнить монстров?»

Произвольно, в смысле Скайрима — не получится и не надо обещать. Спавнить *через пайплайн игры* тёплый тип в тёплой зоне — получится, после SpawnProbe. Для Nightmare правильный путь всё ещё LOT/хук чтения emId, не консольный `spawn daimon`.

> «Там миллионы классов, оставим людям мапу.»
