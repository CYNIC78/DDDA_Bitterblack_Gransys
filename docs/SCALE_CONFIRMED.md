# Масштаб существ — ПОДТВЕРЖДЁН НА ЭКРАНЕ

Статус: **работает.** Гоблин виден в игре высоким и тощим сразу после
загрузки, без перезахода.

## Поле

```
body + 0x60   float   ширина  (W)
body + 0x64   float   высота  (H)
body + 0x68   float   глубина (D)
```

Множители, `1.0` = ванильный размер. **Неуниформные** — три оси
независимы, поэтому размер даёт не только рост, но и телосложение.
Читаются движком каждый кадр: правка видна немедленно.

## Доказательство

Лог теста 09 (билд 21), список живых врагов:

```
[0] uEm8000  0x10DD0060  scale=(1.105, 1.234, 1.261)
[1] uEm0100  0x10DD7320  scale=(0.900, 1.233, 0.913)   <- гоблин
[2] uEm8000  0x10DE0060  scale=(1.325, 1.296, 1.578)
[3] uEm8000  0x10DE7320  scale=(1.113, 1.298, 1.216)
[4] uEm8000  0x10DF0060  scale=(1.566, 1.362, 1.109)
[5] uEm8000  0x10DF7320  scale=(1.290, 1.312, 1.486)
```

Значения гоблина воспроизводятся нашей формулой точно:

```
body=0x10DD7320, want=1.233, jitter=0.30
  j1=-0.8997  j2=-0.8653
  W = 1.233*(1-0.30*0.8997) = 0.900     лог: 0.900
  H = 1.233                  = 1.233     лог: 1.233
  D = 1.233*(1-0.30*0.8653) = 0.913     лог: 0.913
```

Высота 1.233 при ширине и глубине 0.90 — это ровно тот «высокий тощий
гоблин», который появился на экране. **Цифры в памяти совпали с картинкой.**

Каждая особь получила свой размер (`1.233 … 1.362`) — хеш от адреса тела
работает как признак особи.

## Почему кнопка FORCE «не работала»

Она работала. Лог:

```
ForceScale: uEm0100 0x10DD7320 +0x60 ... wrote=0.600 after=(0.600,0.600,0.600)
scale 1.233 -> uEm0100 0x10DD7320 (3 fields) was=0.600 applies=3
```

Запись проходила, гоблин сжимался — на один кадр. Через ≤150 мс `Tick`
видел «значение не из ini» и восстанавливал своё. Эффект был короче,
чем время реакции глаза.

Решение — режим **HOLD** (билд 22): `FORCE` исключает тело из тика,
пока не нажат `RELEASE`. В панели горит жёлтый индикатор.

## Единственное реальное вмешательство движка

Одна строка во всём логе:

```
scale 1.233 -> uEm0100 0x10DD7320 (2 fields) was=0.900 applies=2 reverts=1
```

`2 fields` вместо трёх. Тик хотел `(0.900, 1.233, 0.913)`, а записал
только два поля — значит одно уже совпадало. Поскольку `was=0.900` это
высота... нет: `was` печатает `ch` (высоту). Высота была `0.900`, то есть
**движок сбросил высоту к значению ширины**, а W и D остались нашими.

Похоже на пересчёт при смене состояния/анимации: движок трогает `+0x64`
отдельно от `+0x60/+0x68`. Случай единичный (1 раз на ~5 применений),
тик его исправляет за 150 мс.

**Вывод:** постоянная сверка в тике — правильная архитектура, отказываться
от неё в пользу «записал один раз» нельзя.

## Что это даёт продукту

Размер как признак особи (идея из плана):

- крупный гоблин — вожак, задира, бьёт сильнее;
- мелкий — трусливее, быстрее, первым бежит;
- `scaleJitter` даёт телосложение: коренастые и долговязые в одной стае.

Ключевое: **разнообразие видно мгновенно и не требует новых моделей.**

## Ограничения

- Клампы: `scale 0.7…1.4`, `jitter 0…0.35`. За пределами ломается
  соответствие хитбокса модели и анимация начинает «плыть».
- Хитбокс и урон масштабируются ли — **не проверено**. Следующий тест.
- На других видах (`uEm0200` волк, `uEm0500` огр) поле не проверялось,
  но структура тела общая — ожидаем то же самое.
