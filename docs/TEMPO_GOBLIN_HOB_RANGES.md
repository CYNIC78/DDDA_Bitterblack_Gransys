# Гоблины и хобгоблины: темп атак и скорость — что стоит сейчас

Справка на 2026-09-26 (сборка 85.35). Числа — фактические, посчитаны по коду
и проверены перебором адресов тел (не «примерно»).

---

## 1. Коротко: где что лежит

| Слой | Что задаёт | Где лежит | Правится без пересборки? |
|---|---|---|---|
| **Базовый** (с рождения, всегда) | скорость бега и темп замаха **всех** монстров | `ddda_ai_overhaul.ini`, `[monsterTempo]` | **да** |
| **Разгон по приказу** (ярость директора) | потолки: докуда особь разгоняется на приказе | `src/monsterai/SpeciesCard.h` (код) | **нет, только пересборкой** |
| Сила удара | множители урона | `ddda_entities.ini` | да |
| Адреналин (всплеск урона) | пик силы удара на приказе | `ddda_entities.ini` | да |

То есть: **базовые диапазоны сегодня ОБЩИЕ для всех видов** (одна пара чисел на
всех монстров), а персональные числа есть только у потолков ярости — и они в коде.

## 2. Базовые диапазоны (одни на всех монстров)

Файл: `ddda_ai_overhaul.ini`, секция `[monsterTempo]`

    factorMin = 1.05      # скорость бега, нижний край
    factorMax = 1.20      # скорость бега, верхний край
    animFactorMin = 1.05  # темп замаха/удара, нижний край
    animFactorMax = 1.15  # темп замаха/удара, верхний край
    animAttacksOnly = on  # ускоряется только бой, а не вся анимация
    animCoupling = 0.00   # скорость и темп удара независимы

Как это работает: каждой особи при спавне достаётся **своё** число внутри
диапазона (детерминированно по адресу тела). Два гоблина рядом бегут с разной
скоростью — это и есть разброс, из-за которого нельзя выучить дистанцию.

Жёсткие пределы движка (дальше — рассинхрон хитбокса): бег **0.75…1.30**,
замах **0.70…1.40**. Что бы ни было в ини, значения зажимаются.

## 3. Потолки разгона у гоблина и хоба (код)

Ключевое: потолок берётся **не с потолка**, а как «место в диапазоне».
Особь, которая бегает у верхнего края своего разброса, получает и верхний край
потолка ярости. Поэтому никто не отказывается разгоняться — проверено перебором
200 000 адресов тел: отказов **0** у всех четырёх видов.

### Гоблин `uEm0100`

| | бег | замах/удар |
|---|---|---|
| Без приказа (всегда) | 1.05 … 1.20 | 1.05 … 1.15 |
| Приказ «услышал рог» (уровень 0.65) | +0 … +6% к своему бегу | +5 … +6% к своему замаху |
| Приказ «хват / спасать» (уровень 1.00) | +0 … +9.5% (в среднем **+4.6%**) | +7.8 … +9.5% (в среднем **+8.7%**) |
| Потолок разгона | 1.15 … 1.20 | 1.15 … 1.24 |

### Хобгоблин `uEm0101`

| | бег | замах/удар |
|---|---|---|
| Без приказа (всегда) | 1.05 … 1.20 | 1.05 … 1.15 |

## 4. Два слабых места, которые видно в числах

**1. Самый шустрый гоблин (хоб) на приказе НЕ ускоряется.**
Потолок разгона по бегу — 1.20, и это ровно верхний край базового диапазона.
У особи, которой уже достались базовые 1.20, разгон равен нулю. В среднем по
пачке приказ даёт по бегу всего +4.6%.

**2. У хоба разгон замаха почти не виден: +2.6 … +4.8%.**
У гоблина та же ситуация даёт +7.8 … +9.5%: у хоба потолок замаха специально
ниже (тяжёлый, бронированный, «естественный темп замаха»), и в бою это
выглядит как «хоб на приказ не реагирует» — хотя реагирует, просто слабо.

Обе вещи лечатся числами, а не кодом: поднять потолок разгона у вида так, чтобы
он был **выше верхнего края базового диапазона** (для бега — выше 1.20).

## 5. Что ещё стоит держать в голове при подборе

* **Разброс размера у этих видов уже работает** (коридор из карточки вида,
  потому что в `ddda_entities.ini` размер стоит 1.0): гоблин 1.00…1.15,
  хоб 1.00…1.14. Крупный добивает дальше — на масштаб завязана вся геометрия
  (радиус замаха, дальность прыжка).
* **Скорость от размера не зависит:** компенсация частоты шага срабатывает
  только для особей мельче 1.0, а наш коридор начинается с 1.0.
* **Сила удара** сейчас ×1.12 у всех (боссы зафиксированы на ванилле), плюс
  адреналин — отдельные ключи в `ddda_entities.ini`.
* **`animCoupling`** — одна ручка, если захочется «кто быстро бегает, тот быстро
  и бьёт». Сейчас 0.00: ручки независимы.

## 6. Правка чисел вида — теперь в ини (85.36)

Числа по-прежнему живут в `src/monsterai/SpeciesCard.h`, но это только значения
ПО УМОЛЧАНИЮ: рабочая копия читается из `ddda_ai_overhaul.ini`, секция вида.

    [species.uEm0100]      # гоблин
    rageLocoMin = 1.15     # бег: нижний край потолка
    rageLocoMax = 1.20     # бег: верхний край
    rageAnimMin = 1.15     # замах: нижний край
    rageAnimMax = 1.24     # замах: верхний край
    tempoRage   = 1        # 0 = вид не разгоняется вообще

Ключа нет = число из карточки, то есть старый ini ведёт себя как раньше.
На первом запуске недостающие ключи дописываются в файл сами (с текущими
числами), поэтому вписывать руками ничего не нужно. Правка применяется при
следующем запуске игры.

Что охраняет код (чтобы правка не сломала механизм молча):

* число ниже базового диапазона поднимается до базового, в лог уходит
  `numbers raised to safe: ...` — иначе приказ отбился бы на каждом теле, а в
  игре это выглядело бы как «монстры перестали реагировать»;
* числа зажимаются в пределы движка (бег 0.75…1.30, замах 0.70…1.40);
* перевёрнутый диапазон (низ выше верха) и низ, равный верху, чинятся:
  профиль с нулевой шириной модуль разгона не принимает вовсе.

Проверки: `tools/tcomp/species_tuning_test.cpp` (11 сценариев, в гейте шаг
2i/10), плюс проверки формы в шаге 10/10. Мутации «убрать зажим ниже базы»,
«убрать пределы движка», «игнорировать tempoRage» — все три RED.

## 7. Как подбирать числа вида (шпаргалка 85.37)

Всё, что нужно, выводится из одной формулы: **эффект приказа для особи = её
потолок / её база** (`effective = база + (потолок − база) × уровень`, при полном
приказе уровень = 1). Поэтому по краям пачки:

    самая ШУСТРАЯ особь:  потолокMax / 1.20   (верх базы бега)
    самая МЕДЛЕННАЯ:      потолокMin / 1.05   (низ базы бега)

для замаха знаменатели другие: верх базы 1.15, низ 1.05.

### Бег: что даёт верх потолка (низ потолка 1.16)

| верх потолка | самая шустрая | самая медленная | в среднем |
|---|---|---|---|
| 1.20 (как сейчас) | **+0.0%** | +10.5% | +5.0% |
| 1.22 | +1.7% | +10.5% | +5.9% |
| 1.24 | +3.3% | +10.5% | +6.7% |
| 1.26 | +5.0% | +10.5% | +7.6% |
| 1.28 | +6.7% | +10.5% | +8.5% |
| 1.30 (предел движка) | +8.3% | +10.5% | +9.4% |

Правило: **хочешь, чтобы отклик на приказ видела вся пачка — держи верх
потолка от 1.26.** Тогда даже самая шустрая особь получает не меньше +5%, и
разброс буста по пачке сужается (было 0…+9.5%, станет +5…+10.5%).

### Что стоит сегодня

| вид | бег (шустрая…медленная) | замах (шустрая…медленная) |
|---|---|---|
| волк | +4.2%…+14.3% | +9.6%…+14.3% |
| гоблин | **+0.0%**…+9.5% | +7.8%…+9.5% |
| хоб | **+0.0%**…+9.5% | +2.6%…+4.8% |
| ящер | +1.7%…+14.3% | +7.0%…+14.3% |

Нулевой буст по замаху не встречается нигде — там потолки выше базы (1.15).
Проблема живёт ровно в одном месте: потолок бега, равный верху базы (1.20).

### «Замах должен быть быстрее бега»

Здесь важно различать два слоя, иначе правка не даст того, что ждёшь:

* **Без приказа** соотношение задаёт ГЛОБАЛЬНАЯ база (`factorMin/Max` против
  `animFactorMin/Max`), а не числа вида. Сегодня база замаха (1.05…1.15) ниже
  базы бега (1.05…1.20) — то есть в покое монстры машут медленнее, чем бегают.
  Хочешь «машут не медленнее» — поднимай базу замаха, например до 1.10…1.20.
  Это глобально: касается ВСЕХ монстров, не только гоблинов.
* **На приказе** соотношение задают потолки вида: у гоблина потолок замаха
  (1.24) выше потолка бега (1.20) — то есть в момент события гоблин ускоряется
  в ударе сильнее, чем в беге. Это уже так.

Две оговорки, обе проверяемые:

1. **У конкретной особи каналы независимы.** Место в разбросе бега и место в
   разбросе замаха — два разных ролла от адреса тела. Поэтому «машет быстрее,
   чем бежит» верно В СРЕДНЕМ, а не для каждой особи: быстрый бегун может быть
   медленным махальщиком. Если хочется правило, а не среднее, есть готовая
   ручка `animCoupling = 1.0` («кто быстро бегает — тот быстро бьёт»): она
   связывает роллы, и при базе замаха 1.10…1.20 замах становится не медленнее
   бега у КАЖДОЙ особи. Но связка тоже глобальная и меняет характер всех
   монстров, поэтому включать её — отдельное решение.
2. **Поднимая базу, поднимай и потолки.** Защита в коде не даст потолку уйти
   ниже базы (поднять приказ выше базы нельзя), но поднятый низ потолка до
   уровня базы превращает буст самой шустрой особи в ноль. Так что после
   правки базы замаха правь оба края потолков вида, например у гоблина:
   `rageAnimMin = 1.16`, `rageAnimMax = 1.30`. В логе при неверных числах
   появится `numbers raised to safe: ...` — это не ругань, а подсказка, какие
   числа надо поднять.
