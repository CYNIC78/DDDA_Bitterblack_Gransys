# Архитектура мутаций — что позволяют дампы билда 06

Два дампа (бой + труп) ответили на главный вопрос и заодно перевернули
прогноз, который я давал в `WHAT_WE_HAVE_NOW.md`. Разбираю по фактам.

---

## 1. Главное открытие: объект действия ПЕРЕИСПОЛЬЗУЕТСЯ

Я предполагал, что Act-объекты создаются и удаляются на переходах, и потому
подмена опасна. **Дампы это опровергли.**

```
uEm0100 @0x10DD7320   +2DC8:
   бой    ptr=0x10DC44E0  vt=0x01585BF4  cEm0100ActAtckPutWeapon
   труп   ptr=0x10DC44E0  vt=0x01581A2C  cEmActActingDie
                ^^^^^^^^^^ адрес ТОТ ЖЕ
```

Проверено на всех 6 акторах: **адрес объекта стабилен, меняется только
vtable**. Это классический `placement new` в один переиспользуемый буфер.

Подтверждение рядом: `+0x2DC0` = `cActionManager::cActBank` (36 B), и он
тоже стабилен (`0x10FA4BC4` в обоих дампах). Банк действий держит буфер,
FSM конструирует в нём нужное состояние поверх предыдущего.

### Что это меняет

| было (прогноз) | стало (факт) |
|---|---|
| объект создаётся/удаляется на переходе | буфер один, живёт всегда |
| подмена рвёт жизненный цикл | жизненный цикл идёт через `cActBank` |
| уровень 3 почти закрыт | уровень 3 **возможен**, но через банк, не мимо него |

**Важно:** это не разрешение писать в `+0x2DC8` руками. Это значит, что
правильная точка входа — `cActionManager` (116 B) / `cActBank`, то есть
попросить банк переключить состояние штатно. Мы всё равно не рвём FSM.

## 2. Полная карта одного врага (из живого дампа)

Гоблин `0x10DD7320`, тело 29 632 B. Всё найдено автоматически, имена от игры:

| оффсет | объект | зачем нам |
|---|---|---|
| `+0x0364` | `uModel::Joint` | скелет |
| `+0x0FB0` | `cEfcMotSync` | синхронизация эффектов с мотионом |
| `+0x1C20` | `MtArray` (в теле) | контейнер |
| `+0x1EFC` | `uRagdollExt` | физика трупа |
| `+0x1F18` | `cRigidBody` (в теле) | физика |
| `+0x2110` | `rSoundRequest` | звук |
| `+0x2128` | `rEffectProvider` | эффекты |
| `+0x2710` | `rStatusParam` | **статы/состояния — кандидат на дебаффы** |
| `+0x29AC` | `rShlParamList` | **параметры из `.shl` (`colTimer`, `at_0/1/2`)** |
| `+0x2B98` | `uPlayer` | **цель!** (в трупе уехал на `+0x2FA0`) |
| `+0x2DC0` | `cActionManager::cActBank` | **банк действий** |
| **`+0x2DC8`** | **текущий Act** | **состояние** |
| `+0x2E64` | `cAICtrl` (704 B) | **принятие решений — сюда за весами** |
| `+0x2E70` | `cNeck` | поворот головы/взгляд |
| `+0x322C` | `uCmc` | контроллер движения |
| `+0x6040/48` | `uEm0100_0`, `uEm0100_3` | подтипы/экипировка |

Это карта не «гоблина», а **любого** `uEm*` — оффсеты одинаковы у зайцев,
и `uNpc` тоже отдал `cNpcActWalk` по `+0x2DC8`.

## 3. Как ложатся твои два слоя

### Слой 1 — веса активностей (не ломая FSM)

Цель точная: не «сделать гоблина быстрее», а **убрать окна тупости** —
моменты, когда низкоуровневый монстр стоит и ждёт, пока его бьют.

Рычаги, все найдены:
- `cAICtrl` **704 B**, живёт по `+0x2E64` — ближайший к решению объект;
- `cEvaluation` 10 452 B + `cEvaluationData` 652 + `cEvaluationPoint` 20 —
  система оценки;
- `cAIPriorityThink` 1020 B + `rAIPriorityThink::cOrderValue` **12 B**
  (вероятно `{id, weight, flags}`);
- `cThinkFSM::cThinkFSMParamDisableFlag` (8 B) — **штатный** запрет состояния.

Подход: не выдумывать новое поведение, а сдвигать вероятности уже
существующего. Гоблин остаётся гоблином.

### Слой 2 — скорость на спавне, с разбросом

Твоя мысль про «не статично, а RNG по диапазону» — правильная, и я бы
усилил её одним уточнением: **разброс должен быть на особь, а не на вид**.
Тогда пачка перестаёт быть однородной, и игрок не может выучить один тайминг.

Точки приложения:
- `cMotionCtrl` (96 B) — множитель темпа анимации;
- `+0x29AC rShlParamList` — оттуда идут `colTimer_0/1/2` и `at_0/1/2`,
  то есть окна атаки; менять их **вместе** с темпом, иначе хитбокс
  разъедется с анимацией;
- `cLayoutSetDynamic::cLotData` (112 B) — момент спавна, где особь
  получает свои числа.

**Держать 1.0–1.5.** Анимация несёт тайминги ударов; выше — рассинхрон.

## 4. Билд 07 — что добавлено

`ProbeSidecars`: при HUNT снимается по 128 байт заголовка с трёх объектов —
`cActBank` (`+0x2DC0`), текущий Act (`+0x2DC8`), `cAICtrl` (`+0x2E64`).
В json появилась секция `sidecars`.

Зачем: чтобы найти поля весов и темпа, нужно **сравнить одно и то же место
в разных ситуациях**. Байты сами по себе бесполезны, разница — нет.

### Что снять (2–3 дампа, один гоблин)

| дамп | ситуация | почему важно |
|---|---|---|
| A | гоблин спокоен, не видит тебя | база |
| B | гоблин в бою, атакует | что меняется при агрессии |
| C | *(если несложно)* гоблин воет/таунтит | отдельный режим |

Диффом `sidecars[]` между A и B я найду в `cAICtrl` поля, которые
переключаются вместе с поведением, — это и есть кандидаты в веса.

## 5. Честный статус

- **Чтение состояний — закрыто.** Работает на врагах, зайцах и NPC.
- **Слой 2 (скорость на спавне)** — ближе к реализации: точки известны,
  риск низкий, эффект заметен сразу.
- **Слой 1 (веса)** — нужен диф `cAICtrl`, без него правка вслепую.
- **Подмена состояния напрямую** — теперь технически ближе, чем я думал,
  но по-прежнему **не первый инструмент**. Сначала веса.
