## 2. P0 — то, что может крашнуть или тихо сломать

### P0-2 Кривой указатель ≠ HardReset (SoT §11.3)
`Rd/WrSafe` глотают AV и возвращают false, но `AdmitDirectorMobilization` проверяет только `body!=0` и вид, не `RegionOk` и не DTI тела. Повторный Admit по stale ptr продлевает TTL envelope. `AnimTick` при нечитаемом ряде делает `continue` — envelope живет.
**Риск:** тело умерло между тиками, мы держим его в `g_ownedWolf` и пишем в чужой heap.
**Фикс:** в `Admit` добавить `RegionOk(body, minSize)` + `NameOfLiveObject==expectedKind` перед каждым refresh.

### P0-3 Records переживают мир
`ReadPartyCombatSnapshot` = true на одних записях даже на load screen / в Рифте. Write-path закрыт, но advisory PackMark при `s_nView==0` может жить. Сейчас закрыто через `ExactPartyIdentity` + Aggro bridge, но стоит один раз забыть вызвать `OnWorldUnload` — будет призрачный фокус.
**Фикс:** добавить assert/логику: если `WorldScan` публикует empty world (timestamp=0), `Director::Decide` обязан сбросить mark немедленно, не через 500мс.

### PartyStatus размер
`PartyStatus.cpp` discovery `kPartyBodyBytes = 0x5A40` — 23104 B, больше чем оба TypeAtlas size (uPlayer 23056, uCmc 22752). 48-352 B за хвостом ловятся SEH, но может подцепить чужой heap-объект как ребенка (ложный cAICtrl / cStatus).
**Фикс:** привести к `kPartyBodySize` / `kCmcBodySize` строго.

### CombatBus deadlock
Слушатели вызываются под `SRWLOCK exclusive`. Если модуль в колбэке вызовет `Subscribe/Unsubscribe/PublishWorld/LastReport` — deadlock или рекурсия. Сейчас в коде модули не делают, но контракт не запрещает.
**Фикс:** либо копировать список слушателей под локом и вызывать вне лока, либо задокументировать в `FIX_RULES` как запрещенный паттерн + добавить `try-lock` assert.

## 3. Архитектурный долг

### 3.1 Monster Director — нет HP врага
PackMark считает `huntScore = highestAbsHP / currentAbsHP` по **партии**, не по монстрам. `uEm*` HP до сих пор UNVALIDATED. Мы выбираем фокус по раненой пешке, а не по раненому волку. Работает как костыль, но не как тактика.
**Идеи:** 
- искать HP через `cCharParamEnemy` / `cStatus` inline как в Possession (0x2698) — нужен A/B как для Drenched.
- или хотя бы ввести прокси-метрику: `enemyCombatCount`, `inCombatAction`, время в бою.

### 3.2 Tempo хук хрупкий
`movss xmm6,[esp+30]` — сигнатура 317 хитов, контекст 3 store `esi+40/44/48`. Любой патч игры / другой мод может сломать.
**Фикс:** добавить второй якорь — DTI-имя `cEm*` рядом, или валидацию что `esi` указывает на `SpeciesCard`-допущенный вид перед записью. Уже есть `DirectorReady`, но в naked хуке проверки нет.

### 3.3 Possession — poke vs thiscall (уточнено 2026-09-21)
84.30-84.37: poke массива статусов ≠ apply. 84.31 live: `applied id=7 t=5400 count=1` → `failed why=watch-engine-cleared`. Движок стирает неполный набор. Сейчас работает через thiscall `0x8342f0` (`cStatus+0x7C`), но `FindId(rec,7)` сразу -1 в том же кадре (слой C не синхронен с E). WATCH 2.5с, custom xmm inject только на наш Set.

**Уточнение от пользователя (верно):** vanilla `id=7` = триггер боя, а в бою сейв заблокирован (`ESC+I` не работает). Значит сам статус сайдкар НЕ требует — он не переживет сейв по дизайну игры. Подтверждено комьюнити: "You can save anywhere if you are outside of the combat" и "can't save mid battle".

**Где сайдкар нужен:** не для статуса, а для Nightmare latch:
```
вектор BBI-лут (вне боя, можно сейв) → latch → пешка пала → подъем → Set id=7 (в бою, сейв закрыт)
```
Между вектором и падением, и между подъемом и следующим боем — сейв возможен. Latch = `DDDA_AI_Overhaul/nightmare_latch.json` (vector, stage, episodes).

**Текущий статус:** `Possession.cpp` — рабочий primitive, но не используется в продукте (только F12). Оставлен как функция для будущей системы. Гейт `TargetStanding()` уже есть, `cPlReviveCMC` ванильный cure — не вешаем Set на revive (FIX_RULES §3).

**Edge:** с `dinput8` модами сейв в бою разблокируется ("dinput mod. You can save even during combat"), тогда статус мог бы сохраниться. Но это уже зона чужого мода, не наша.

### 3.4 PawnAI_BusOrchestrator порядок
`cordon` должен идти последним (ставит потолок Guardian). Если завтра добавим новый модуль, порядок неявный. `SAFE_MODULE` глотает exception и просто `enabled=false` без лога.
**Фикс:** явный приоритет модулей + лог в `logFile` при SEH.

### 3.5 Audio dead code
`AUDIO_RUNTIME_EXPERIMENTAL=0` гейтит, но 1450 строк `AudioRedirect.cpp` все еще компилируются в DLL. Увеличивает размер, путает новичков.
**Фикс:** вынести в `src/audio/experimental/` и исключить из `vcxproj` в дефолте, оставить только хедер с `Init()` заглушкой.

### 3.6 Спавн — мутируем заспавненное, а хотим управлять спавном

**Сейчас:** `MonsterDirector + MonsterTempo + SpeciesCard` — мутируем то, что уже заспавнилось: множители `+0x0EE4…+0x0EF4`, `AggroWatch` pin, `scale` 0.93..1.15 с защитой альф. Это LIVE слой, безопасно.

**Хотим:** заставить игру спавнить то, что мы хотим, а не то что в статике `.lot`.

**Что известно из разведки (`archive/SPAWN_SYSTEM_RECON.md`):**
- Иерархия: `rLayout (1144 B) → cLayoutSetEnemy (152 B) → cSetInfoEnemy (272 B) → cSetInfoEnemy0100 (288 B)` — на каждый вид свой класс записи.
- `cExtGroupSetCondition (28 B)` — условие появления группы.
- `rLayoutGroupParam (584 B)` — параметры группы.
- `rAIDynamicLayout (104 B)` — динамическая расстановка.
- Файлы `.lot` лежат в архивах карт `stage/`, не в `em0100.arc`. Формат XFS, как `*.prp/*.sn2`, парсер уже есть в `ASSET_FORMATS.md`.

**Два пути (оба нужны):**

**Путь Б — из файлов (начинать с него):** Распаковать `.lot` из `stage/` через ARCtool, разобрать XFS нашим парсером. Плюс: видим всю карту, включая незагруженное, без риска краша. Минус: статика без состояния. Даст карту `cSetInfoEnemy0100` 288 B для проверки размера.

**Путь А — из памяти:** Найти живой `rLayout` текущей карты, пройти `cLayoutSetEnemy → массив cSetInfoEnemy*`. Плюс: видим что реально загружено + состояние. Минус: надо найти корень (сигнатура/DTI scan).

**Как технически заставить спавнить другое (гипотезы для проверки, без кода до фактов):**
1. **LIVE мутация записи до спавна:** `cSetInfoEnemy.kind` / `count` / `condition` — если успеем до создания тела, игра создаст наше. Это все еще LIVE, не PACK. Нужно найти момент создания (брейк на конструкторе `cSetInfoEnemy0100` по фабричному RVA из `types.tsv`).
2. **Подмена через `cExtGroupSetCondition`:** условие группы — 28 B, можно временно сделать `true/false` для управления появлением.
3. **Хук спавн-функции:** найти функцию которая берет `cSetInfoEnemy` и спавнит `uEm*`, подменить `enemyId` на входе (как мы делали с `CreateFile` для музыки, но для спавна). Требует сигнатуры.
4. **PACK как последний:** свой `.lot` — только если LIVE отказывает. По `ARCHITECTURE.md` PACK только после доказанного отказа LIVE.

**Почему Nightmare — оркестратор последним:** Когда будут готовы Director, Tempo, Aggro, PartyRecon — Nightmare просто дергает их с долгосрочной памятью (sidecar `nightmare_latch.json` + Encounter Memory `cellHash = hash(mapName, floor(x/cell), floor(z/cell))` из `ENCOUNTER_MEMORY_DESIGN.md`). Сам не пишет в тела, только в примитивы.

**Следующий шаг по спавну (1 вечер):** Путь Б — достать 1 `.lot` из `stage01` архива, прогнать через `tools/xfs_tree_dump.py`, найти `cSetInfoEnemy0100` и сверить 288 B.

## 8. Слабые места по сложности — HP / урон монстров (вопрос пользователя)

**Что сейчас есть в `EnemyTuner` / `CharParamEnemy.Generated.h`:**
- `cCharParamEnemy` 320 B лежит в теле `uEm0100 +0x5870 / +0x59B0`, находится по сигнатуре `cam_near 500 / mid 800 / far 1200 / death 1500`.
- Поля подтверждены: `+0x0C attack, +0x10 defense, +0x14 magick_attack, +0x18 magick_defense, +0x100 return_activate, +0x104 return_duration, +0x12C scale`.
- Сейчас пишем: масштаб `+0x60/64/68` (genetic-scale), поводок `+0x100/104`, броня на возврате `+0x10/18` (Sanctuary).
- **Универсального current HP в `uEm*` НЕТ** — SoT §13 UNVALIDATED. `human_hp +0xDC` — не live HP. Party HP есть в `record+0x96C`, вражеского нет. Поэтому PackMark считает по HP партии, а не врага.
- **Урон:** поля `attack/magick_attack` есть в charparam, но в продукте не крутятся (только defense в Sanctuary). Можно крутить так же транзакционно как scale.

**Почему игра легкая как чародей без апгрейдов:**
- Мы ускорили темп (`1.20..1.25`) и масштаб, и сделали `DirectorFocusSet` pin, но не трогали цифры урона/брони. Чародей ваншотит, т.к. `defense` врага ванильный.
- `CombatIntel` ловит урон, но не меняет его.

**Инструмент урона — как сделать (1 вечер, без нового оффсета до A/B):**
1. Расширить `EntityCfg::Tuning` — `attackMult, defenseMult, magickAttackMult` (как `scaleMin/Max`). Clamp 0.5..3.0.
2. В `TickOneBody` добавить `ApplyCombatStats` — пишет в обе копии `cCharParamEnemy +0x0C/10/14/18` = `base * mult`, с `readback + WATCH`.
3. Хант HP: A/B — бьем гоблина, дампим тело до/после через `EnemyTuner` FieldScan, ищем float который упал на величину урона и монотонно падает. Окно `+0x0..+0x58E0` без `+0x40 xyz` и `+0xEE4 tempo`. Это даст live HP.
4. Дамаг-хук (если charparam не влияет на итоговый урон): найти функцию урона по сигнатуре, как Tempo `movss`, и множить `xmm`.

**Быстрые win на 1 вечер (укрепляем слабые места, не новые фичи):**
- P0-2 фикс: `RegionOk + DTI` в `AdmitDirectorMobilization`
- Логирование SAFE_MODULE падений
- Вынос аудио dead code из сборки
- `bump_build.py` — авто-поднятие тега + проверка `analyze_devtools_layers`
- `attackMult/defenseMult` в `ddda_entities.ini` + `ApplyCombatStats`

#### §8 Combat stats — attackMult/defenseMult (главное)
- **Файлы:** `src/EntityConfig.h/.cpp`, `src/EnemyTuner.cpp`, `ddda_entities.ini`, `src/DefaultEntitiesIni.h`, `docs/AUDIT_2026_09_21.md`
- **Было:** мод был лёгким как sorcerer без апгрейдов потому что менял только tempo/scale/aggro, а не цифры урона/брони. `cCharParamEnemy +0x0C/+0x10/+0x14/+0x18` были известны но не крутились (только defense в Sanctuary).
- **Стало:**
  - `Tuning` расширена: `attackMult, defenseMult, magickAttackMult, magickDefenseMult` float 1.0 ваниль, Clamp 0.5..3.0 (`ClampCombat`).
  - `ini` + default header: секция `[default]` теперь содержит 4 ключа с комментарием про per-pack variance и транзакцию.
  - `EnemyTuner::Touched` — `baseAtk/baseDefC/baseMAtk/baseMDefC`, `cur*`, `haveCombat`, `combatRoll*` (0.9..1.1 детерминированный хеш `body>>3 ^ salt`).
  - `ApplyCombatStats(body, rec, tuning, kind)` — находит `cCharParamEnemy` по кэшированному off (или scan), читает 4 поля, запоминает ваниль при первой встрече, считает `want = base * mult * roll`, пишет в обе копии `+0x140`, readback WATCH (drift лог), логирует первые 2 применения.
  - Per-pack variance: два гоблина рядом получают разные роллы (напр. 0.93 и 1.07) — нет одинакового урона/брони, как просил пользователь.
  - Sanctuary интеграция: `ApplyReturnSanctuary` теперь не дерётся за защиту — база для буста = `curDefC/curMDefC` (боевая с mult+roll), а при выходе восстанавливает боевую, не ваниль.
  - `TickOneBody` — вызов `ApplyCombatStats` до Sanctuary, с условием `mult!=1.0 || haveCombat` чтобы держать roll.

#### Как пользоваться (оркестратору):
- `ddda_entities.ini` `[default]` или `[em0100]`:
  ```
  attackMult = 1.4        # враги бьют на 40% сильнее
  defenseMult = 1.5       # толще на 50%
  magickAttackMult = 1.3
  ```
