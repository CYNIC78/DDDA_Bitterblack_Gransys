# Разбор полевого лога 85.96-basesplit (бой, 05.10)

Лог: `uploads/ddda_ai_overhaul.log`, 580 строк, сессия ~56 минут
(`t=3398109 ms` ≈ 56.6 мин). Билд в первой строке: `85.96-basesplit (compiled
Oct 5 2026 05:52:22)`.

---

## 1. Ini пересоздан — обход сработал

```
Config: added missing key [species.uEm0200] tempoRage = on (new option, default written)
Config: added missing key [species.uEm0101] tempoRage = on ...
```

Всего 81 строка `Config:` — файл создан с нуля и наполнен бэкфиллом. Запуск
удался, потому что ini на момент старта уже существовал: это билд **85.96, а не
85.97**, то есть починки падения при отсутствии ini в нём нет.

## 2. Карточка хоба больше не перебивается зажимом

```
Monster Director: species uEm0101 rage ceilings run 1.17..1.20 swing 1.10..1.18
                  (base run 1.05..1.20 swing 1.05..1.15)
```

* `1.17..1.20` — низ ярости приехал из свежего ini, карточка не перебита;
* `numbers raised to safe` — **0 вхождений** во всём логе. До 85.96 здесь было
  бы `rageLocoMax raised(1.15->1.20)`;
* `director-mobilization-baseline-outside-profile` — **0 вхождений**.

Строка `base run 1.05..1.20` печатает ГЛОБАЛЬНЫЙ диапазон (`GetRange`), а не
базу вида — так и задумано: база вида применяется внутри `FactorFor`.

## 3. Темп хоба — числа воспроизведены, а не прочитаны на глаз

Взял хеш (`HashUnit`, финализатор murmur3) и соли (`kSaltLoco = 0`,
`kSaltAtk = 0x9E3779B9`) прямо из `MonsterTempo.cpp` и посчитал, что обязан был
выдать `AnimFactorFor`/`FactorFor` для адресов из лога.

| тело | что | лог | расчёт 85.96 | расчёт до 85.96 |
|---|---|---:|---:|---:|
| 0x11106780 | замах | 1.015 | **1.015168** | 1.065168 |
| 0x11497470 | замах | 1.035 | **1.035112** | 1.085112 |
| 0x111F0060 | замах | 1.015 | **1.014923** | 1.064923 |
| 0x11150060 | замах | 1.037 | **1.037306** | 1.087306 |
| 0x11166360 | замах | 1.062 | **1.061949** | 1.111949 |
| 0x11497470 | бег | 1.137342 | **1.137342** | 1.185394 |

Совпадение до четвёртого знака при точности лога `%.3f` — все шесть. Четыре из
шести старый код выдать не мог в принципе: они ниже 1.05, а и карточный, и
глобальный диапазон замаха до 85.96 начинались с 1.05.

**Вид тел взят из явных строк лога, а не из имени действия.** Хобы пользуются
актами `cEm0100Act*`: `GuardianDoctrine: ... 0x11150060 (uEm0101)` (строка 243),
`EnemyTuner: scale 1.433 (base 1.411 LEADER) -> uEm0101 0x11166360` (строка 223).
Первая моя попытка прочитать вид из `cEm0100ActThrowStone2` дала «гоблин» и
числа не сошлись — сошлись, когда вид взят из явных строк.

**Итог по запросу владельца.** Спокойный замах хоба 1.015..1.062 при базе
гоблина 1.05..1.15 — хоб медленнее гоблина и в замахе тоже, как и просили.
Бег 1.137 при новом пределе 1.15 (было до 1.20).

## 4. Чего этот лог НЕ проверяет

1. **Разгон хоба по приказу.** `Monster Director: disabled`, `tacticsActuator=OFF`,
   `observerOnly=1 writes=0`, `policy ENGAGED` — 0 вхождений. Приказов не было
   вовсе, поэтому «разгон снова жив» по этому логу не подтвердить. Нужен заход с
   включённым `[monsterAI] enabled = on`.
2. **Верх лестницы.** `rank summary total=6 uEm0100:0 6 0 0 0` — шесть гоблинов,
   все `soldier(1)`. Ни минибосса, ни элиты (вес минибосса 0.02).
3. **Починка 0xc0000142** — это 85.97, здесь её нет.

## 5. Что ещё видно в логе

* **Три строки `has invalid value`** (`chantNearest`, `pawnFinish`,
  `parallelOrders`) — косметика свежего ini: ключ ещё не дописан, а чтение уже
  состоялось, и «ключа нет» напечаталось как «неверное значение». Умолчания
  (1, 1, 0) совпадают со значениями прежнего ini, поведение не поменялось.
  Ключи есть и в эталоне, и были в живом ini — расходится только сообщение.
* `PackObserve: MIXED uEm0100=1 uEm0101=6` — пачка из шести хобов и гоблина.
* Ванильный масштаб хобов 1.411..1.517 — сходится с замером 85.85 из
  `SpeciesCard.h` (1.41..1.60), то есть относительный коридор 1.00..1.05 сидит
  на правильной базе.
* `engineReverts` 1..2 у четырёх тел — известное поведение (движок откатывает
  наши записи размера), задокументировано в 85.40.
* `slow-ticks worst=14234ms ofWhichOurs=9` — счётчик интервалов между тиками;
  14 с при 56-минутной сессии это загрузка/меню, а не просадка в бою.
* `LogMem: faults=10202 dumps=63 sites=1` — обработчик отработал штатно, один сайт.

## 6. Исход этого разбора (85.98)

Числа из раздела 3 легли ниже гоблиньих 1.05..1.15, и это оказалось лишним:
просьба владельца касалась только верха БЕГА (1.20 -> 1.15), а скорость
замаха — показатель сложности монстра. В 85.98 низ базы замаха поднят
1.00 -> 1.03, то есть хоб теперь 1.03..1.10. Те же тела по той же формуле
дадут 1.045..1.092. Бег (1.02..1.15) и ярость (1.10..1.18) не тронуты.

## 7. Что нужно от следующего захода

1. Билд **85.97** — тогда можно снова удалить ini без риска.
2. `[monsterAI] enabled = on` — иначе разгон хоба не проверить.
3. Дожить до пачки с минибоссом, если интересен верх лестницы (пункт 3.2 аудита:
   сегодня минибосс даёт защиту x1.50 = 210 при 240 у гримгоблина).
