# DDDA AI Overhaul Mod — Research & Architecture Analysis

## 📁 Архитектура ddda-dinput8 (референс)

### Принцип работы
- **Прокси-DLL**: `dinput8.dll` подменяет настоящую — игра сама загружает мод
- **MinHook**: библиотека для перехвата функций (x86 detours)
- **Сигнатурный поиск**: адреса ищутся по байтовым паттернам (`0xCC` = wildcard)
- **ImGui + D3D9**: оверлей в игре (F12)
- **Конфиг**: `dinput8.ini`

### Ключевые глобальные переменные
```cpp
BYTE **pBase;   // База данных персонажа
BYTE **pWorld;  // Мировые данные (аугменты, баффы, уровни)
```

### Полезные макросы
```cpp
GetBasePtr<float>(offset)        // Чтение из *pBase + offset
GetWorldPtr<T>({o1, o2, o3})     // Цепочка указателей из *pWorld
Hooks::FindSignature(name, sig, &ptr)  // Поиск по сигнатуре
Hooks::CreateHook(name, addr, handler, &orig, enable)  // Установка хука
Hooks::Set<T>(addr, {values})    // Запись байтов напрямую
```

### Документированные оффсеты (из PlayerStats.cpp)
```
База игрока:              0xA7000
├── +0xDD0:   Level (UINT16)
├── +0x994:   XP
├── +0x6E0:   Vocation
├── +0x96C:   Stats (HP, Stamina, Strength, Defense, Magic, MDefense)
├── +0x96C+0x1224: Pawn Inclinations (9 значений float)
│       Scather, Medicant, Mitigator, Challenger,
│       Utilitarian, Guardian, Nexus, Pioneer, Acquisitor,
│       Skill use
├── +0xA7808: Equipped Skills
└── +0xA7E00: Learned Skills

Main Pawn:                +0x7F0
Pawn 1:                   +0x7F0 + 0x1660
Pawn 2:                   +0x7F0 + 0x1660 + 0x1660
```

## 🔬 Уровни моддинга AI в DDDA

### Уровень 1: Инклинации (уже доступно через dinput8!)
- **Где**: `baseOffset + 0x96C + 0x1224`
- **Что**: 9 float-значений склонностей пешки
- **Эффект**: Меняет приоритеты поведения (атака ближних/дальних целей, лечение, сбор и т.д.)
- **Реализация**: Простое изменение значений через `GetBasePtr<float>()`
- **Идеи для оверхаула**:
  - Динамическая смена инклинаций по ситуации (в бою vs вне боя)
  - Адаптивные инклинации: анализ врага → выбор контр-стратегии
  - «Умные» инклинации: Utilitarian + Scather против крупных врагов, Challenger + Mitigator против групп

### Уровень 2: Редактирование .arc файлов (как Lefein's World Difficulty)
- **Где**: `nativePC/rom/game_main.arc` (основной) + `nativePC/rom/enemy/*.arc` (враги)
- **Инструмент**: ARCtool (FluffyQuack) + `-xfs` флаг
- **Форматы**:
  - `.xfs` → `.xml` — геймплейные переменные и скрипты
  - `.lot` → `.txt` — спавн врагов и их параметры
  - `.fsm` — Finite State Machine (AI-поведение!)
- **Что редактировал Lefein**:
  - AI врагов: агрессия, тактики, использование скиллов
  - Поведение пешек: приоритеты использования предметов и скиллов
  - Параметры врагов: здоровье, защита, резисты
  - Условные спавны

### Уровень 3: DLL-хуки AI-функций (через dinput8)
- **Где**: Исполняемый код `DDDA.exe`
- **Метод**: Сигнатурный поиск → MinHook → перехват функций принятия решений
- **Пример из блога omni**: `DDDA.exe+332605` — чтение здоровья игрока
- **Сложность**: Высокая (нужна IDA/Ghidra, нет RTTI)

## 🌙 Nightmare Module — Bitterblack Gransys (техразбор)

### Идея
После убийства Деймона (вторая форма) Грансис превращается в «большой Остров»:
- Вечная ночь
- Мрачная вулканическая погода
- Местные монстры заменены на BBI-«родственников»

### Технический вердикт: ✅ РЕАЛИЗУЕМО

Разбор по компонентам:

| Компонент | Оценка | Инструмент | Статус в коде |
|---|---|---|---|
| Вечная ночь | 🟢 Легко | Хук HTimeInterval (уже в dinput8) | Код написан, нужен оффсет часа |
| Погода | 🟢 Легко | `GetBasePtr(0xB8780)` — прямая запись | Готово |
| Триггер (флаг Деймона) | 🟡 Средне | Cheat Engine + DDsaveTool | Ручной триггер готов, авто — в поиске |
| Замена монстров (статическая) | 🟡 Средне | ARCtool `-lot` + своп .arc файлов | Таблица маппинга готова |
| Замена монстров (динамическая) | 🔴 Сложно | Хук спавн-функции в DDDA.exe | Будущее |

### Детали реализации

**Вечная ночь:**
- В динпут8 есть `realTime` режим: `HTimeInterval` перехватывает добавление времени
- При `mTimeInterval == 0` время останавливается
- Дополнительно: найти оффсет текущего часа и принудительно держать в диапазоне 0–5

**Триггер:**
- Нужно найти флаг прохождения квеста «Сердце Тьмы» (Heart of Darkness)
- Альтернативы: проверка количества убийств Деймона, наличие предмета
- Поиск через Cheat Engine: два состояния (до/после) → сканирование changed/unchanged
- Пока: ручная кнопка в UI

**Замена монстров (статический .arc):**
1. Распаковать stage100*.arc (Gransys) через ARCtool `-lot`
2. В .lot.txt заменить ID врагов: гоблин → greater goblin, волк → warg, циклоп → gorecyclops и т.д.
3. Запаковать обратно в `nightmare_game_main.arc`
4. При триггере: переименовать файлы (game_main.arc ↔ nightmare_game_main.arc)
5. Минус: нужен перезапуск игры. Плюс: 100% надёжно.

**Замена монстров (динамический хук — будущее):**
1. Найти в DDDA.exe функцию, читающую enemy ID из LOT-данных
2. Поставить хук через MinHook
3. В хуке: сверить ID с таблицей маппинга → подменить на BBI-вариант
4. Плюс: мгновенно, без перезапуска. Минус: нужен глубокий реверс.

## ⚠️ Известные проблемы и техдолг (CombatIntel / Damage Tracking)

- **Дистанция и идентификация фауны**: мирные зверьки (`uEm8600` Hare / Rabbit) в редких случаях могут перекрываться базовой структурой драконьей группы `0x61` из-за сходства фабрик MT Framework. Вынесено в техдолг для дальнейшей калибровки.
- **Хит-дебаунсер**: комбо-атаки и многоударные скиллы требуют тонкого окна сглаживания (120-150 мс), чтобы физические суб-тики движка (`mHPCurrent` / `mHPRecoverable`) строго ложились в формулу «1 взмах = 1 хит».

## 📷 Исследование камеры: Кастомная дистанция, FOV и коллизии (Camera Distance & Zoom)

### Как устроена камера в движке MT Framework:
1. **`uCameraGame` / `uCameraCtrl` / `rFollowCameraParam`**:
   - Адрес структуры позиции камеры: `g_camPos` (хук `HCam1` в `CameraPlus.cpp`).
   - Адрес структуры ориентации и расстояния: `g_camOrient` (хук `HCam2` в `CameraPlus.cpp`).
   - По смещению `[g_camOrient + 0x150]` игра держит базовую дистанцию следования / зум (`Follow Distance`).
2. **Коллизия со стенами (Wall-Hug Zoom)**:
   - Движок выполняет трассировку луча (`sCollision::ScrColInfoCastConvex` / `rAHCamera`) от головы персонажа в направлении камеры на расстояние $D$.
   - Если луч встречает препятствие на дистанции $d < D$, камера принудительно подтягивается к игроку на $d - \text{margin}$.
3. **Как сделать ползунок Camera Distance**:
   - В хуке `HCam2` перехватывается загрузка дистанции `[esi + 0x150]`.
   - Умножение на кастомный множитель `g_camDistanceMult` (0.5x ... 3.0x) или прямое смещение `g_camDistanceOffset` позволяет отодвигать или приближать камеру без искажения перспективы!
