# AUDIO_MUSIC_RECON — музыкальный слой (слой 0: сцена/атмосфера)

**Статус:** замысел согласован, кода нет, решения принимаются по протоколу R0→R4.
**Зачем документ:** зафиксировать рамку до первого кода (по `FIX_RULES`: сначала факты,
потом вмешательство). Если файл разойдётся с реальностью — править файл,
а не реальность (по `VISION`).

---

## 1. Замысел

Дать игроку свою музыку **в рантайме**, из папки мода, без правки файлов игры,
без хекс-редакторов и перепаковки arc. Движок остаётся дирижёром (когда играть,
переходы, громкости, катсцены) — мы меняем «пластинку», не дирижёра. Это прямое
продолжение философии `VISION.md` «меняем контекст, не решения» на аудио-домен.

**Почему это часть нашего мода, а не отдельный релиз:** только у нас есть живой
контекст (CombatBus, MonsterDirector, SpeciesCard, Nightmare-latch). Статичный
заменитель файлов этого не видит никогда. Развитие = вариант C (контекстный выбор).

**Рамка:** музыкальный модуль — «слой 0» (атмосфера). Не pawnai/monsterai код,
не правки AI/статов. Сам модуль живёт в `src/runtime/` (`src/audio/`),
конфиг — свой ini-sidecar, off-by-default, vanilla fallback при любой
неизвестности. Сейв неприкосновенен. Мод шипится **без музыки** — только
загрузчик + папка (юридическая чистота).

## 3. Архитектура MVP (вариант A + обязательный патч размера)

**Конструктивно редирект и патч размера — ОДНА фича.** Редирект без патча =
крашгенератор (см. §2). Патч без редиректа бессмыслен.

```text
движок:    сцена → запрос трека (открывает *.sngw через CreateFile)
хук:       имя есть в нашем маппинге?
             нет  → пропускаем в оригинал (ванила/чужие музмоды не тронуты)
             да   → выбор из пула (RNG в MVP; в C — контекст)
                    ├─ CreateFile отдаём наш файл
                    └─ размер: GetFileSize(наш файл) → транзакционная запись
                       в запись .stq в памяти (validate → write → readback →
                       watch → rollback по канону ARCHITECTURE §4.2)
движок:    играет как обычно (луп, громкость, переходы — его забота)
```

Свойства:

- **Выбор — на каждый запрос трека**, не раз на сессию. Пулы работают «разная
  музыка на каждый заход к Деймону».
- Файлы в пуле могут быть **разной длины** — размер подставляется под выбранный
  файл в момент выбора. У статик-мода на ID один размер навсегда, у нас — по файлу.
- ini хранит **только имена** файлов. Размер — авто. Луп-точки — не раньше
  доказанной нужды (R2).
- Всё состояние — в памяти процесса и наших ini. Файлы игры и `bbs_rpg.arc`
  не трогаются вообще. Выход из игры = чистая ванила.

### 3.1 Иллюстративный контракт ini (не реализация)

```ini
[music]
enabled = 0

; одиночная подмена
map.Gazer            = music/bbi/gazer_theme.ogg

; RNG-пул: каждый заход — случайный из списка
map.Shinigami_Battle = music/bbi/death_1.ogg | music/bbi/death_2.ogg | music/bbi/death_3.ogg
```

### 3.2 Первая волна контента (scope MVP)

Остров ББИ, уникальные имена, дискретные боссы — удобный A/B стенд:

- Смерть (`Shinigami_Battle`)
- Прикованный циклоп
- Проклятый дракон (`Lich_ZonbiDragon`)
- Тёмный епископ
- Глаз (`Gazer`)
- Деймон (`Demon_1`, …)
- Сет из 3 боевых треков острова по тиру сложности

### 3.3 Авторский канон первой волны (контент-замысел)

- **Лейтмотив:** хор «испорченных пешек» — под властью чёрной магии острова
  пешки «подпевают» монстрам на арене, как оккультная группа поддержки.
  Исполнение натужное: подчиняются чужой воле, сопротивляться не могут,
  и понимают инверсию своей миссии.
- **Резонанс с механикой мода:** та же инверсия, что в Nightmare-ярме
  (пешка пала → встала чужой). Слой 0 доносит историю, которую слой 1
  показывает геймплеем. Нарратив без квестов, катсцен и текста.
- **Миксы:** оркестровый «голливудский» и тяжёлый (metal + symphonic).
  Оба живут в пулах ini одновременно — разные размеры допустимы
  (размер подставляется под выбранный файл, §3).
- **Язык хора:** латынь (ритуальная глубина) и/или английский (игрок
  улавливает сюжетную подкладку). Открыто; система не ограничивает —
  разные языковые версии = разные позиции пулов.
- **Эскалация хора по тирам:** бой 1-го тира — далёкий шёпот,
  2-го — распознаваемый чант, боссы/3-й — полный хор.
- **Будущее правило варианта C:** при активном Nightmare-latch одержимой
  пешки — принудительно «хор-вариант» боевого трека: твоя пешка поёт им.

## 4. План B: паддинг вместо патча памяти

Если live-запись в .stq окажется недостижимой (таблица не находится / движок
кэширует размер на загрузке и не перечитывает): инструмент конвертации **дополняет
OGG-пользователя до точного размера из .stq** валидным контентом контейнера
(VorbisComment произвольной длины; точность до байта). Тогда хватит чистого
редиректа без единого байта записи в память. Цена: файлы раздуваются, пул
должен быть выровнен под один размер. Не цель — страховка.

## 5. Открытые вопросы (в порядке протокола)

1. Где физически лежит размер после загрузки .stq: сырой буфер ресурса
   или распарсенные поля в `sSoundManager`-иерархии? (старт: DTI `sSoundManager`)
2. Перечитывает ли движок размер **на каждый запуск трека**? Если кэширует
   однажды — переключение размера «на лету» невозможно, пулы = одинаковый
   размер (или план B).
3. Точная карта имена↔триггеры ББИ (инвентаризация `wave/` в R0 + лог R1).
4. Параметры Vorbis для стримера (rate/channels/quality).
5. Открывает ли движок файл разово или подцикливает хэндл; есть ли кэш меню/титров.

## 6. Протокол

- **R0 (оффлайн, без игры):** инвентаризация `wave/*.sngw`; разбор `bgm.stq`
  из `bbs_rpg.arc` (arctool → сырой дамп; кандидат под тулзу в `tools/`);
  черновая карта имён/триггеров из описаний существующих музмодов.
  Выход: CATALOG-док `docs/generated/BGM_MAP.md` + формат .stq (таблица полей).
- **R1 (read-only, игра):** пассивный лог обращений к `sound\stream\bgm\wave`
  (какой файл, когда, с какого потока). Никакой записи. Подтверждение §2/§5.
- **R2 (MVP):** хук + выбор + запись размера транзакционно (`FIX_RULES` §4б:
  write → readback → WATCH 2–3 с → rollback). Приёмка: заданный трек ББИ
  заменяется, без краша, луп ровный, после боя — обычная музыка; отключение
  модуля без перезапуска = ванила.
- **R3:** развитие маппинга до полной первой волны (§3.2) + конвертер
  Suno→ogg (отдельная тулза или инструкция; ffmpeg).
- **R4 (вариант C):** контекстный выбор через CombatBus: вид босса из
  SpeciesCard/бестиария, ночь/день, остров/материк, Nightmare-latch.
  Правила — в ini (веса/условия). Только после подтверждённого R2.

Стингеры посреди играющего трека (напр. на «срыв темпа» из `VISION`) —
потребность варианта B (свой миксер). Не цель текущего трека; фиксируем,
чтобы не обещать лишнего.

## 7. Риск-реестр

| Риск | Митигация |
|---|---|
| Размер кэшируется на загрузке → разные размеры в пуле невозможны | R2 A/B; план B (паддинг) |
| Запись в .stq-таблицу не находится | план B; деградация в «подмена только равных размеров» |
| Хук на аудио-потоке | в detour — ничего тяжёлого; пути резолвим заранее, без локов и логов |
| Кривые параметры ogg юзера | конвертер + валидация при загрузке (отказ → ванила, строка в лог) |
| Ожидание «динамической музыки AAA» | рамка зафиксирована выбором на границе трека |

## 8. Границы (явно)

- Не трогаем AI, статы, баланс, сейв — отдельный модуль, отдельный ini.
- Не шипим музыку в моде/репо; только загрузчик и схема конфига.
- Не обещаем интерактивные стингеры до варианта B.
- Не ломаем чужие музмоды: нет нашего маппинга — файл проходит как есть.
